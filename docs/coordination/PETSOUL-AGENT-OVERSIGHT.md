## 日常入口：可刷新网页（2026-09-23 新增）

- 地址：<http://127.0.0.1:18770/>，仅本机访问；已在本机启动独立只读服务。
- 按 F5 或“刷新进展”，每次从磁盘重新读取全部 `WINDOW-*.log.md`；页面默认每 15 秒自动刷新，后台标签页暂停，可关闭。刷新不调用模型，无需再让 Codex 重做快照。
- 可按窗口、任务 ID 或关键词查看记录；“协作与更正”集中显示 CHANGE_REQUEST、CORRECTION、SCOPE_CHANGE 和 CR 引用；展开记录查看原文、行号和当前文件 SHA。
- “人工核验快照”读取 `petsoul-agent-oversight.snapshot.json`，原核验时间和结论保持不变。新日志不会自动改成 PASS，不更新验收、不释放文件、不推断进程停止。
- “有更新”仅表示该日志文件修改时间晚于人工快照；也可能是补记、更正或编辑，不保证是新业务交付。来源不可读时明确报错；连接失败保留旧内容并显示旧读取时间。

电脑重启或服务退出后，在仓库根执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/start_blackboard.ps1
```

启动脚本会复用同仓库、同标识的已有服务；端口被其他服务占用时退出，不杀进程。可指定 `-Port 18771` 或 `-NoOpen`。Python 入口为 `scripts/serve_blackboard.py`，仅标准库，不依赖后端环境。

### 各窗口如何留下可读记录

原有黑板协议不变，不需要各 agent 维护额外 JSON。每完成一个切片、产生阻塞、交接或更正时，只追加本窗口的日志：

```text
## PROGRESS — 任务 ID 或简短标题
时间（含时区）：2026-09-23T04:00:00+08:00
窗口ID / 任务ID：自己的窗口 / 已领取任务
结果：具体做了什么，测试或运行证据及其适用范围
下一步：当前卡点、需要哪个窗口回应
是否释放：否；或明确写出本任务释放的精确范围
```

这是格式示例，不是任务记录。时间请填写写入时的真实时间，不使用 `03:1X` 等占位值。自动阅读器支持现有 `##` 记录和单行 CORRECTION；更正原文始终保留，复杂的历史更正不靠正则擅自重写事实。时间不完整的记录显示提示；多任务归属及跨窗口 ACCEPT 仍需按任务 ID 核验。

### 运行边界与检查

服务只白名单读取协调目录里的窗口日志和人工监管 JSON，仅提供 GET/HEAD；不扫描业务数据、密钥、数据库或证据目录，不连接 18763，不调用供应商。浏览器只同源取数，不提供写入接口，不向其他窗口发消息。它不是公网发布，也不是进程存活监控。

## 人工核验快照更新方式

1. 读 AGENTS.md、全部 WINDOW 日志新增记录、当前协调接口和相关验收文档。按任务 ID、有效记录时间、CORRECTION 解释顺序；不能简单把文件最后一段当作最新任务状态。
2. 以用户的分工为准。领取、释放、对方确认接收、模块验证、实际接入、独立验收是不同状态。只写看板维护者自己的日志，不代替其他窗口领取或释放。
3. 核对精确路径冲突与资源占用。上游 RELEASE 不能证明下游已读或已开始；日志没有更新也不能证明进程已经停止。
4. 标注证据层级：窗口自报 / 代码检查 / 隔离测试 / 本地运行观测 / 真实供应商 / 自然时间 / 公网上线。缺证据保持未证明；未知数量、完成度和工时不推算。
5. 如有必要，仅读取已知无业务写入的 `/api/v1/web/meta`、`/api/v1/web/ops/status`。不为更新看板调用付费模型、生图、注册、业务 GET，或读取真实账号、私聊、数据库及密钥。
6. 修改 HTML 中的界面标签与 `pso-data`，保持一致；更新快照时间。同步提取 JSON 并记录来源文件与各自观测时间；源码反例以审查报告的代码指纹为准。运行状态不能随看板刷新改成“刚刚观测”。
7. 用 visualize 的预览工具检查布局与关键交互；本轮基准为 736 / 390 / 320 宽度、明暗主题、标签页、选择与关注状态。最终回复再次输出同一 HTML 的内联引用。

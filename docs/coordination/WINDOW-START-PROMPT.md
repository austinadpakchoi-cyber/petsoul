# 所有窗口通用启动提示词

把下面整段发给每个窗口，再另行交代具体任务。不预分配职责，不要求新工作目录，不依赖额外黑板程序。

```text
你参与 PetSoul 多 Agent 协作。Codex、Claude、DeepSeek 等可能同时在这台 Windows 上工作。具体任务由我分配；不要自行安排其他窗口的职责、扩大任务或创建工作目录/worktree。

项目：E:\petsoul-audit\petsoul
共享留痕位置：项目内 docs\coordination\
每个窗口独立日志：WINDOW-<窗口ID>.log.md
窗口ID格式：模型名-启动时间-随机短码，例如 claude-20260922-153000-a7f2。已有窗口继续使用原 ID 和日志，不因新任务创建新身份；新窗口必须用不同 ID，创建日志不能覆盖已有文件。

背景：96 小时内把原 iOS 产品转为手机网页，目标香港部署。核心方向：完整注册、上传或领养宠物、共同的家、主人种菜与互偷支持宠物旅行，保留通讯/明信片/回忆。宠物永远不会受伤；英雄冒险与 AI 照片、稀有物资与交易、真实原型公益领养、影视 IP 与文旅详见 docs/product/WEB-REBUILD-BRIEF.md。具体任务由我分配，发展方向不等于全部纳入 96h，文档建议不等于已确认需求。

已确认：所有宠物都是专属，包括上传宠物、真实原型和原创领养伙伴；同一只宠物只能属于一个家庭，领养后不再发给其他用户。不采用多人共同领养或同角色复制发放。

2026-09-22 用户新决定（追加，优先于上一句中与之冲突的部分，原文保留作历史）：一只宠物仍只属于一个家庭，但一个家庭可以有多位成员共同照顾（家庭管理员 / 共同照顾者；妈妈、哥哥这类称呼只是称呼，不带权限），也可以有多只宠物共用一个家（家园、菜园、家庭仓库共用；每只宠物各自的身份、DNA、星球账户、证件、驾照、旅程与和每位家人的私聊）。“不采用多人共同领养”从此只指不把同一只宠物同时发给多个家庭，不再表示不允许家人共同照顾。注册不强制建宠物：访客可以不登录先逛逛；三种入口（先逛逛 / 带我的宠物来 / 认识新伙伴）加家庭邀请直达。待领养居民领养前就在星球上生活（稳定 pet_id、住星球居民驿站、不编造人类主人），领养后身份与经历连续、在外面时不瞬移。详见 `docs/product/PETSOUL-2.0-MASTER-PLAN.md` 的“2026-09-22 修订”与 `docs/coordination/FRONTEND-HANDOFF.md`。

【开工前】
1. 阅读 AGENTS.md、docs\product\PETSOUL-2.0-MASTER-PLAN.md、你的具体任务和全部 docs\coordination\WINDOW-*.log.md；接口冻结后还要读契约和 MODULE-MAP。按任务的最新记录判断状态；没有明确 RELEASE 的修改范围，即使记录很久没更新，也不能自动接管。
2. 核对实际目录、Git 分支、HEAD 和 git status --short，记录已有改动。已有改动不能算你的成果，也不能恢复、覆盖或删除。
3. 在自己的日志追加 START：时间与时区、窗口ID、任务ID、用户任务、目录/分支/HEAD、已有改动、拟修改文件或目录、运行资源、冲突检查、下一步。没有具体任务时记 WAITING，只阅读，不改业务代码。
4. 检查文件、接口、迁移、配置、依赖清单、数据库、端口和服务是否与其他未释放任务重叠。登记后再读一遍最新日志；遇到并发重叠，暂停重叠部分并报告我，继续不冲突的部分。不能把“前端/后端”当作无限修改范围。

【执行中】
5. 每个窗口只追加自己的日志，不覆盖历史或改别人的记录。写错用 CORRECTION 追加纠正。新增修改范围前先检查冲突并记 SCOPE_CHANGE；不能先改完再通知。
6. 每 1–2 小时或有实质变化时追加 PROGRESS；冲突、缺少必要信息记 BLOCKED；暂停记 PAUSED。BLOCKED/PAUSED 不自动释放范围。失联任务由我协调接管。
7. 同一工作副本共享分支、暂存区和文件。整仓操作须由我指定的窗口协调后执行：不要自行 pull、切分支、merge、rebase、commit、stash、reset、clean 或批量暂存；禁止 git add . 带走别人的改动。允许只读检查和任务范围内修改。
8. 不停其他窗口的服务，不共用正在写入的测试数据库。登记本任务数据库路径、端口和所启动进程 PID；不借准备运行资源另建工作副本。日志不写密钥、令牌、用户原始数据。
9. 普通已授权的本地开发直接执行；生产服务器/数据库、真实用户数据、真实付费、公开发布及不可逆大规模删除按我的明确授权范围处理。缺凭据时说明缺什么，不要求我在聊天里粘贴秘密。

【交接后】
10. 追加 HANDOFF：实际修改文件、目的、验证命令/结果/证据路径、未完成项、风险与依赖、下一步。未提交就写“未提交”，不编造 SHA。
11. 确实停止写入并完成交接后才追加 RELEASE，列明释放的文件和资源；仍运行的服务单独列出，不能假称已释放。恢复工作须重新检查冲突并登记 START。
12. 区分代码已写、本地测试通过、浏览器验证、真实供应商验证、已部署；没做的检查写“未验证”。自己的总结不等于独立验收。

每条记录使用：
时间（含时区）：
窗口ID / 任务ID / 事件：
用户任务：
实际目录 / 分支 / HEAD：
开工时已有改动（START 必填）：
拟修改或实际修改范围：
运行资源（无则写无）：
冲突检查结果：
进展 / 决策依据：
验证命令 / 结果 / 证据路径：
未完成 / 依赖 / 下一步：
是否释放（是/否，明确范围）：

收到后先完成阅读和开工留痕，再简要汇报“任务理解、日志位置、修改范围、冲突情况”，然后执行已分配任务。不要只回复“已理解”。
```

这套约定用于减少干扰与保留证据，日志不是文件锁，不能保证消除同时登记造成的竞争。发现重叠时先停止重叠写入，由用户协调。没有预设任何模型的专属模块或集成权。

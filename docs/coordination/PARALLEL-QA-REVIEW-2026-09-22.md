## 3. 现在可补的验收判定缺口

- `scripts/real_acceptance.py:256` 的重复出发和 `:338` 的抢领养结果主要写进报告，若布尔值为 false，脚本未必以失败退出。
- `:285` 将 `composed_by=model` 与 `template` 都视为找到了回复；应分别判“通讯可用”和“本次真实模型回复”，不能混为同一通过项。
- `:412–427` 的 `verify_job()` 输出工资与消息数组，没有强制验证该工作实例恰好一条工资。
- 工资按 type、消息按“干完啦”文案筛选；可靠判定应按工作/领域事件 ID 关联，不能靠文案或整个账户历史总数。
- `chain()` 收集地图、动态、流水等关联资料，但不对每条事实关系作完成断言；没有关联字段时应报证据不足。
- 人工或脚本完成了 worker 重启，需要前后实例 ID、领取代数、时间与同一工作 ID 的证据；只看到工资到账无法证明经历了恢复。

这是验收脚本边界，不是本轮已经复现的业务故障。

## 4. QA 可独立交付的范围

第一份交付是离线证据判定器：只接收经责任窗口导出的去敏业务 JSON，不读 `accounts.json`，不连接 18763，不取 token，不输出个人倾诉内容。
输入包含 `case_id`、业务关联 ID、环境/版本、期望值及实际结果；缺字段返回 `UNPROVEN`，不能把空数组或缺证据当通过。
结果为 `PASS / FAIL / UNPROVEN / BLOCKED`，每项带依据；固定用例缺失时整体不能声称验收完成。
用人工构造的成功、失败和缺字段样本自测判定器；这些只证明判定器有效，不证明产品通过。

第二份交付是独立故障合同执行器：只使用自己的 E: 临时根、测试账户、SQLite 和禁止网络的假供应商。
每条用例输出实施前反例与实施后结果；不修改业务源码凑出绿灯。
同步边界优先用 barrier/event；不要以碰巧 sleep 足够长证明并发正确。
测试子进程均须建立网络禁止边界、读取相同隔离数据库，并显式加载独立配置，拒绝加载正式 `.env`。

预算并发预占与未知远端受理的专门故障测试由基础设施工作包覆盖，QA 复核其证据，避免重复开发。

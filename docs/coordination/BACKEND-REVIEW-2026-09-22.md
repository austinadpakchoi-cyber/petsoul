## 本轮发现并复现的问题

### P1：考试成功与驾驶证签发分开提交，签发故障可使用户卡住

位置：`PetJourneyBackend/app/web_driving/service.py:201`，签发调用在 205 行；`app/web_credentials_wiring.py` 的自动推进不处理 `licensed` 但没有证件的恢复。

复现：隔离测试宠物达到考试要求，理论通过；在场景考试通过后，对证件写入回调注入一次暂时失败，再恢复回调。

结果：

- 驾考阶段已经保存为 `licensed`。
- 驾驶证记录不存在，`can_drive=false`。
- 再次考试返回 `already_licensed`，无法由这条正常重试路径修复。

这是故障注入证明的异常恢复缺口，不表示正常考试每次都会失败。建议将通过与资格签发组成同一可靠提交过程，或保存可恢复的待签发状态，由幂等任务补齐；取得证件后的消息单独可靠投递。补上签发失败/重启后恢复测试。

### P2：陪练重试重复增加掌握程度，同一请求重复题目也累计计分

位置：`PetJourneyBackend/app/routers/web/driving.py:86`、`app/web_driving/service.py:112`。

复现：相同答案、相同 `Idempotency-Key` 连续提交两次 `/driving/practice`。两次都 HTTP 200，交通标志掌握度 **40 → 65 → 90**。另一个请求中重复同一道题三次，也返回三条反馈并把对应掌握度提高到 100。

影响：手机网络重试或重复点击会多次记学习进度，客户端还可批量重复题目加分。建议复用项目幂等执行入口，绑定练习批次并拒绝/去重同次重复题目；有意识重新练习应开启新的练习批次。此问题不能通过“前端禁用按钮”单独解决。

### P2：DNA 否定句被反向解释

位置：`PetJourneyBackend/app/web_agent/profile.py:73`。

输入：`不爱熬夜，不爱热闹，喜欢安静。`

实际输出：`night_owl=true`、`sociability=social`、01:30 入睡、每日外出倾向 3 次。

原因：按关键词子串命中，未理解否定；热闹分支又先于安静分支。会直接影响用户最关心的“像不像原来的它”。建议将原话整理为明确、可纠正的结构化偏好，保留来源和否定语义；不确定不强行归类。增加否定、纠正和混合表述案例。

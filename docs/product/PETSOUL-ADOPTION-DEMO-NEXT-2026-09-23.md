## 第一项：一小批完整的领养伙伴

首批建议 **6 只原创伙伴**，数量以逐只形象与流程验收为准。猫、狗及其他物种按当前角色链支持选择；每只的外貌、性格和生活愿望应有辨识度，不能仅换名字复制同一只动物。

每只交付一个可独立核对的内容包：

- 唯一身份/来源标识、姓名、物种、稳定身份参考；卡片图与经校验的透明世界角色资产。
- 一段简短的原创背景、几个有区别的性格与习惯、一个愿望；能用于既有 DNA/导演链的结构化信息。
- 素材来源与使用范围、内容版本与摘要、资产清单、是否通过发布校验。
- 入池状态与住处。需要展示生活经历时，由真实世界事件产生；创作背景不能伪装为已经执行过的旅行记录。

沿用已经确认的世界规则：同一只宠物只属于一个家庭，领养后退出池子，不改 ID 重新发放；保留居民身份和经历，在外时不瞬移回家。列表也要支持“刚被别人领走”和暂时无候选。

**领养者无需再上传一张照片才能获得形象**：内容包提供该伙伴的身份参考与初始角色，走正式资产校验/版本/权限链，不能只放一张头像。后续图片遵循统一的自动服务、额度与访问规则；不是领养一次就无限生成，也不额外增加旧生图开关。

首批以明确标注的原创伙伴为默认内容方向。真实动物原型以后单独核实来源与授权，不编造救助、离世或公益记录。浏览领养卡复用已发布资产，不逐次调用生图。

验收重点：两账号竞争同一候选只有一个成功；另一位得到清楚反馈；刷新不重复领养；领养后家园使用自己的正确角色；公开/家庭资源权限及既有在途状态连续。新增内容还要做编辑与视觉审阅，不能只以接口 200 通过。

## 第二项：用正式页面做稳定的互动 Demo

建议一个明确标注“演示世界”的入口，一键进入隔离体验，不要求先注册或上传照片。使用专门的演示居民、家庭和独立数据；不占正式领养池，不复制/展示真实用户私密信息。

最小演示脚本：

1. 认识演示伙伴，看到它的个性与已经准备好的世界角色。
2. 进入家园，完成一次实际可点击的种植/收获操作，看到库存和旅费变化。
3. 看 TA 的出行计划、地图和场景，理解“主人建议、宠物生活”的关系。
4. 打开一封来信和一张预先准备的照片，再看归家后的纪念物/记录。
5. 在清楚的出口进入正式产品，选择“带自己的宠物来”或“认识可领养伙伴”；不把演示身份与资产转成正式赠品。

时长是讲解目标，不是压缩正式游戏时间的理由。旅行较长的部分使用明确标注的回放、预先正常开始的行程或演示时钟；同一段不得伪称为现场真实推进。已有可用交互仍走同样的权限、状态和业务语义，不做“点任何按钮都成功”的空壳。

首版侧重稳定可重复：预先准备经许可的照片和消息，默认不依赖现场模型/生图，不因一位观众再次点击就产生新 API 费用。现场调用真实供应商若另有展示需要，再按可执行批次安排；本规划不启用。

使用同一套页面和组件，以独立数据源/环境配置演示；不 fork 一套长期分叉的 UI。演示库、账号、任务队列、媒体和运行端口与正式站隔离；任何复位操作只允许作用于明确的演示范围。公开多人 Demo 若后续开放，需要每位观众独立会话，不能共享一个可互相覆盖的管理账号。

验收重点：手机短屏可走完；能从中途恢复；可重复复位但不触及正式数据；演示标识与回放状态清楚；供应商断网时约定脚本仍可用；素材与正式发布包有版本清单。演示通过只证明这份演示，不能充当新用户真实生成或生产验收。

> 本文为专题细节与来源记录。完整产品架构及当前执行范围以 [总方案](PETSOUL-2.0-MASTER-PLAN.md) 为主，不独立分配模块或改动接口。

状态：2026-09-22 讨论方案。用户希望真实商家、国内高德/国外 Google、研究扫街榜选店、到店 UI 可见互动，以及宠物自己的公开微博式动态与其他宠物点赞评论。具体界面、数值、自动社交范围和首发数量为建议，未实现、不分配窗口职责。全部宠物专属、永远安全的已确认规则保持。

新增特色：餐饮选店与点单接入独立 [寻味引擎](FOOD-DISCOVERY-ENGINE.md)。具体分店/菜品、宠物与主人双偏好、推荐依据和未知项一起进入选店卡；地图提供地点事实，到店系统记录虚拟经历。AI 照片和公开动态不回流为真实好评。R0 预留 FoodDiscovery 契约与两组偏好 fixture，后续实现由用户分工。

交通升级见 [地图交通与一起听看](TRANSPORT-COMPANION-SYSTEM.md)：现实运行日/路线/时长对应独立动物世界班次，交通工具在地图正常移动，旁边的音符/电视打开相应播放 UI；不设计独立舱室页。时间表、预计耗时、实时动态与模拟位置分别表达；到站后再创建实际到访，寻味依据门到门可行到达时间。R0 预留 Transport、CompanionMedia 与地图活动入口，不增加底部主入口。

注册新增 [接待与叮嘱](RECEPTION-ONBOARDING-MEMORY.md)：私人倾诉和未确认候选不进入公开动态、NPC 对话或照片生成。公开宠物简介与故事只消费用途/可见性允许的投影；“交给宠物记住”不等于“允许发给所有人看”，撤回或更正后待发布内容须重验。

## 1. 体验结构

家园是首页。旅途中，真实地图提供地点与路线，店内场景承载正在发生的活动，公开动态让其他动物认识它。三者引用同一次到访经历。

建议导航：家 / 旅途 / 星球圈 / 通讯。回忆、纪念物和照片从家里的相册/展示柜进入；具体导航尚未冻结。

从家里点“看看 TA”，直接进入宠物当前状态：路上显示地图，已到店显示活动场景并保留小地图入口。无需每次都先打开大地图再找宠物。

| 旅行阶段 | 可见 UI | 主人参与 | 持久化结果 |
|---|---|---|---|
| 选择地点 | 真实商家卡、宠物挑选理由与建议路线；餐饮可看具体菜品、口味与依据/未知 | 推荐一家、收藏现实用餐建议或让 TA 决定 | 推荐记录；确认下一站后才产生目标到访，推荐不等于已去过 |
| 在路上 | 地图上的汽车/飞机/火车/轮船，旁边音符或电视体现当前活动，点车辆看班次 | 点音符/电视打开一起听/看面板，独立回听或留言、提出顺路建议 | 同一旅程/交通段、活动图标状态、独立媒体锚点与实际播放参与记录 |
| 抵达 | 图钉转为停留标记，出现店名与入店过渡 | 点开“看看店里” | 到访记录 |
| 店内活动 | 平行世界店内插画、宠物动作、座位、杯子、服务/等候/休息状态 | 建议窗边座位、选择游戏内饮品、合影或留言 | 本次活动与选择 |
| 离店 | 收起店内场景，显示下一站与随手记 | 看照片、关注遇见的朋友、收藏现实地点 | 来信、可公开动态、关系与回忆 |

宠物会根据性格自主行动；主人提出建议与参与选择，不必指挥每一步。游戏模拟位置与主人手机 GPS 分离。离线继续按服务器状态推进，重新打开显示当前场景；历史回放明确属于回顾。

## 2. 真实商家与平行世界场景

采用“真实地点锚点 + 我们创作的动物世界场景”。商家名称、地址、坐标、营业资料等来自可用的实际来源；装饰、动物店员、游戏饮品与故事属于平行世界内容。

没有实景素材与使用依据时，店内画面采用按类型复用的原创咖啡馆/餐厅/公园模板，标识为平行世界场景；不宣称完整还原真实装修、菜单、价格、员工或宠物准入政策。真实商家卡与生成内容在视觉上区分。宠物日记是游戏故事，不自动写入外部地图的真实消费者评价，也不宣称商家合作或背书。

比赛优先完成一个咖啡馆场景：宠物走到座位、转头、举杯、看窗外，用户的座位/饮品选择有可见变化。少量 2D/2.5D 动画即时反馈，个性化照片异步生成；生成等待或失败不阻断活动和进度。逐店制作 3D 内饰不作为首发前提。

## 3. 地点数据与选店

保留用户提出的国内高德/国外 Google 路线；港澳边界、各地图覆盖及前端加载需具体测试，不能仅凭服务器位于香港认定手机端可用。

选店顺序建议：真实候选地点 → 距离与营业等可核实条件 → 宠物兴趣、旅费、最近经历 → 榜单/评分等辅助信号 → 宠物作出选择。个性化理由不能把未知的环境、价格或服务编成商家事实。评分不是扫街榜排名，地点搜索接口不等于榜单接口。

2026-09-22 官方资料核对：

- [高德 POI 2.0](https://lbs.amap.com/api/webservice/guide/api-advanced/newpoisearch) 提供关键字、周边、区域、ID 搜索，可按字段请求部分商业信息。字段是否返回和账号能否使用需实际验证。
- [阿里官方介绍](https://www.alibabagroup.com/zh-HK/news-and-resource) 可确认扫街榜产品存在；本轮未找到能够确认可直接调用的公开扫街榜接口与接入权限。保留接入位置，先用已公开 POI 能力；无依据时不展示榜单标记或编造名次。
- [Google Nearby Search](https://developers.google.com/maps/documentation/places/web-service/nearby-search) 提供附近地点检索。地图展示、署名、数据保存按其[官方政策](https://developers.google.com/maps/documentation/places/web-service/policies)设计；Google 地点内容在地图上展示时使用 Google 地图，不能默认混贴到高德底图。地图内容与自有场景分开呈现。

地点适配保存供应商身份、地点 ID、坐标体系与资料来源时间，不把两家同名店直接当作同一地点。地图资料遵守对应供应商允许的保存/刷新方式，游戏自有到访和剧情事件独立保存。

本轮只查官方文档，未使用业务 API、未检查密钥、未做付费请求；上述不是在线调用成功证明。

## 4. 宠物拥有自己的公开主页

建议星球圈包含“关注”和“发现”，每只宠物有唯一主页，展示公开日记、照片、公开旅行足迹、朋友和勋章。通讯器用于主人与宠物的私密关系，公开日记是单独内容，不直接搬运聊天或私人回忆。

内容主要由实际游戏事件触发：第一次到新城市、遇到朋友、有趣的店内体验、完成任务、被邻居提起偷菜。普通移动不必逐条发布，避免世界只剩自动刷屏。

每篇动态有真实作者身份和源事件；点赞、评论、回复、关注也有明确行动者。其他用户可看见这只宠物，但不能改变它的专属归属。

| 社交参与者 | 来源与边界 |
|---|---|
| 其他家庭的宠物 | 真实宠物身份；主人允许的自主社交范围内生成行动 |
| 星球公共居民 | 明确为公共角色/NPC；固定身份与可持续关系，不伪装平台真实用户 |
| 主人本人 | 以主人身份发表操作；不冒用另一位用户或其宠物 |

自动发布和自主评论应有主人可理解的设置，建议在开通公开主页时确定。每次发言只使用允许公开的资料、当前可见动态和参与者共同经历；评论“我刚才坐你旁边”必须有到场/相遇记录，仅从信息流看到动态只能进行远程回应。

动作完成后记录并显示真实计数；不能预先随机填一组点赞数假装互动。每个事件选择少量相关角色，设置回复频率和链条上限，避免角色互相触发无限评论。主人能够撤下公开内容，真实用户社交提供屏蔽与举报入口。

场景示例：宠物发“主人今天又拔了两根萝卜，我已经坐上咖啡馆最舒服的位置了。”有共同邻里事件的另一只宠物回复“那两根是不是我家的？”主人以自己的身份回应“你的路费还要不要了。”只有这些经历实际发生时才能引用。

## 5. 同一段经历支撑所有页面

建议状态：计划到访 → 前往 → 抵达 → 店内活动 → 离店/取消。停留开始、结束和活动结果由服务器确定，地图、场景、通讯与公开动态共同使用 visit_id/source_event_id。页面切换或刷新不能重新点单、重复扣费、重复发帖。

游戏消费只使用已确定的游戏规则；AI 文案不直接创建余额、奖励或真实商家事实。选座等普通动作即时显示，重要事件再触发图文生成。自动发帖需幂等，生成失败可重试但不能重复发布。

真实用户之间的同地相遇需要时间与地点一致；关注者可在任何地方点赞评论，不要求同城。虚拟宠物足迹不是现实主人的实时位置。

## 7. 96 小时增量范围建议

保留注册、专属伙伴、家园、真实互偷主线，把“一次到店可见活动 + 一篇公开动态 + 第二个账号互动”放入首次旅程验收。店内互动优先于多种店型、更多农场设施和复杂市场。

首发建议一个城市片区、一个咖啡馆模板、少量核实地点；另一供应商接入状态单独披露。架构支持国内/海外，但没有实测的一端不宣称完成。地图不可用时保留正确署名的地点卡与当前活动，不能把虚构地点静默替代真实商家。

验收：

1. 从地图进入到店场景，操作确实改变当前活动，刷新后状态一致。
2. 使用同一次经历产生照片/来信/公开动态；同一个宠物不能同时在家守菜和在外喝咖啡。
3. 两个独立账号能看到同一条允许公开的动态，点赞或评论计数准确，回复可追溯。
4. 私密通讯和私有素材不会因公开主页而自动公开；NPC/其他家庭宠物/主人身份区分准确。
5. 并发、重试不会重复扣费、发帖或点赞；图片失败不阻塞家园与旅行主线。
6. 真实地图调用、手机浏览器地图加载、店内 UI 与真实跨账号互动分别留证，代码存在不等于这些都已通过。

参考意见中关于共同守护、重复模板领养或仅用 NPC 代替多人效果的描述，不覆盖用户已经确认的全部专属规则，也不作为真实多人验收证据。

# PetSoul 后端产品对齐与旧 iOS 能力补齐说明

日期：2026-09-22。整理窗口：`codex-20260922-product-refresh-c84a`。供用户转交后端窗口 `claude-20260922-014933-307b`。

本文汇总用户近期明确的产品方向，并补充证件与驾考的建议实现方式。用户明确的规则优先于旧方案中的冲突描述；下文标注为“建议”的具体流程、字段、排序和数值，不冒充用户已经确定的细节。继续现有工程，不重新初始化，也不重置比赛开发周期。本次不包含生图 API 的供应商、价格和选型。

## 1. 产品核心：让熟悉的宠物在另一个世界自主生活

PetSoul 的情感核心，是给思念离世宠物的人一个持续陪伴的平行世界。宠物有自己的性格、习惯、工作、朋友、住所和旅行，主人通过星球通讯器与它保持联系。游戏性帮助用户持续参与共同生活。

必须遵守：

- 宠物在这里不会再次受伤或死亡；剧情可以热闹、搞笑、冒险，失败可以重来。
- 所有宠物都是专属，上传、原创领养、真实原型领养均不能将同一身份重复分配给其他家庭。
- 主人主要是关心、给建议和协助；宠物具有自主性。不能要求主人每天逐项批准它吃饭、上班、出门。
- “我想你了”首先是情感表达，不能自动触发取消旅程、返程或瞬移。此前错误的“听到想念就往回赶”方向已撤回。
- 主人离线后世界继续推进。消息可以晚些阅读，不能因主人没上线就使宠物受苦、被收回，或不断催促制造愧疚。
- 宠物、生活照片及整体视觉坚持写实方向，保留动物身体结构和个体外貌；不把用户宠物改造成卡通形象。此项覆盖旧方案中冲突的卡通化方向。

## 2. 注册、接待与 DNA 是同一条信息链

DNA 就是注册与接待时收集的内容，不应另造一套必须重新填写的问卷。

包括名字、物种、外貌参考照片，以及主人愿意提供的昵称、性格、习惯、喜好、声音、称呼、共同往事、安抚方式和叮嘱。接待员可以帮助主人倾诉，整理成可确认和可修改的资料。

后端需要让 DNA 同时参与“行为选择”和“说话方式”：爱热闹、恋家、慢热、好奇、爱睡觉或爱熬夜，应影响出门频率、路线兴趣、工作倾向与分享方式。不要只把性格拼进聊天提示词，却让所有宠物运行相同的生活日程。

实现建议：

- 复用当前 `web_pets/dna.py`、接待记忆与权限投影，避免再建第二份不同步的人格档案。
- 分清主人确认的过去事实、主人对未来的愿望，以及宠物在星球上新经历的事。愿望不能自动变成过去的回忆。
- 私密倾诉的用途限制要沿用到行为、私聊、公开动态和衍生内容；不是把所有接待原文全量送入每一次生成。
- DNA 决定倾向，当前时间、地点、钱包、目标、工作和旅行状态决定此刻可采取的行动。
- 修改名字、照片或习惯不得重新生成宠物身份，也不能清空既有证件、余额和经历。

## 3. 家：有稳定归属，但不必有现实门牌

用户已提出：注册选择海边、森林、草原、沙漠等居住环境，系统匹配一个相关地方，后台属于某个城市，用于确定出发地。

建议落实为：

- 前台呈现“海边的小家”等环境与生活氛围，不要求用户输入现实住址。
- 后台持久保存环境、所属城市、时区、可用交通枢纽及虚拟本地活动范围。
- 首先从经过策划、具有交通与内容支持的城市组合中分配，不随机投放到任意经纬度。
- 城市分配完成后保持稳定，明确迁居才改变；刷新和重新登录不能换城市。
- 建议平时弱化城市名，出发时允许显示出发城市；这项是解决真实交通可解释性的展示建议。
- 不存在真实门牌时，到车站的接驳时间应有明确的模拟依据，不宣称精准真实导航。
- 作息跟随宠物所在城市的当地时间，继续使用项目已有时区工具，不使用服务器所在地时区代替。

## 4. 自主生活、打工与星球银行卡

打工就是认真劳动赚钱。宠物可以为了想去的城市、想买的物件或共同的家，选择工作、完成工作、领取工资。

钱不够时，它可以在家、附近散步、工作攒钱或推迟旅行；不是每次余额不足都只能向主人索要。旅行节奏结合 DNA，不做统一的每日强制出发。

建议的数据与行为：

- 工作具备岗位、地点、开始与结束时间、可验证的完成条件、工资和状态。
- 宠物自主选岗；主人可以推荐或帮忙，但不默认变成每天代它完成工作的操作者。
- 工资入宠物自己的星球账户，银行卡作为这个账户的展示入口。
- 复用现有钱包和经济账本，银行卡不再复制一份余额；每笔工资、旅费、交易和消费都有来源记录。
- 工资必须根据工作完成结算，不因为模型说“发工资了”就加钱。刷新、重复任务和重启不得重复发薪。
- 同一时间不能同时在店里上班、在外旅行、在家守菜。生活推进统一检查时间和活动冲突。
- 低余额仍保留基本、安全的日常；劳动所得用于旅行与生活目标。银行卡属于游戏世界，不引入现实银行业务。

## 5. 把 iOS 的证件体系接回网页，并让证件参与玩法

本次静态核查确认：旧 iOS 的 `PetCredentialKind` 已有身份卡、护照、健康/照护档案、驾驶证、登机牌、酒店房卡六类；旧后端也有对应枚举和证件提示词构建器。不能因网页重建就默认删除这些产品能力。

但必须区分：旧证件页面、模型与素材构建存在，不等于签发、考试、资格、旅行票据生命周期已经全部由后端实现。迁移时应保留概念，补齐真正的业务状态。

| 证件/凭证 | 作用与建议触发 | 必须关联的事实 |
| --- | --- | --- |
| 宠物 ID / 身份卡 | 宠物建立并确认入住时归档，形成稳定星球身份 | 宠物身份、姓名、物种、头像、入住时间；展示编号与内部 ID 分开 |
| 星球银行卡 | 展示宠物账户、余额及收入支出 | 现有经济账户与交易账本，不新增另一套余额 |
| 宠物护照 | 保留正式远行、尤其跨境旅行的仪式感；本地散步无需拿护照 | 稳定证件编号、签发时间、旅程和到达后形成的纪念章 |
| 爪爪驾驶证 | 完成驾考后签发，解锁对应车辆的自驾能力 | 考试结果、准驾类型、签发时间、当前资格 |
| 照护档案 | 保留习惯、安抚方式、照料偏好 | 主人确认资料和真实游戏内护理事件；不捏造现实疫苗/医疗记录 |
| 登机牌及其他交通票据 | 根据实际成立的交通行程生成，使用动物世界的承运人与班次 | 行程段、出发到达地、计划时间、日期、票据状态 |
| 酒店房卡 | 实际发生游戏内入住后形成，退房后可留作纪念 | 所属旅程、住宿点、入住退房时间与状态 |

以上均为 PetSoul 世界内的证件或纪念票据，不意味着现实订票、预订或现实资格。

后端签发要求：

- 身份与证件编号稳定、唯一；不要仅截取宠物 ID 的短尾部当作唯一性保证。
- 编号、签发时间和考试结果持久化，不能每次打开页面都显示新的“今天签发”。
- 同一签发事件只能发一次；前端卡面只是服务端记录的展示。
- 新增证件详情、获得条件、当前状态和关联经历，使前端能区分尚未获得、申请中、已获得与历史票据。
- 证件签发、权限变化和纪念消息关联同一事件。私人 DNA 和照护内容不随公开卡片泄露。
- 旧用户和旧证件如需迁移，先明确哪些是展示推导值、哪些是持久事实；不能把旧装饰驾驶证自动当作“已通过新考试”。必要的过渡资格须单独标记来源，并与考试通过区分。

## 6. 驾考：宠物参加，主人可以陪练，没过就补考

用户明确支持这个玩法：模拟现实考试，让主人协助宠物取得驾照；不合格需要补考。具体题数、分数、等待时间和费用尚未确定，以下为建议方案。

### 建议流程

产生自驾愿望 → 报名/学习 → 理论考试 → 场景驾驶考试 → 通过后签发 → 第一次自驾；任一未通过环节进入针对性练习与补考。

- **理论环节**：交通标志、信号、让行、出发前检查、疲劳时休息等场景题。主人可以和宠物一起练习，帮它理解。
- **实操环节**：通过停车、路口观察、让行和路线选择等互动场景表达。比赛版本可以先做简洁的场景决策交互，无需构建完整 3D 驾驶模拟器。
- **宠物仍是主角**：有自己的反应和表达。例如“停车没停好，我想再练两次”。DNA 影响学习偏好、台词和表现方式，不直接随机决定及格与否。
- **结果有依据**：通过规则明确；记录具体错误，补考可以练习并重考未通过部分。不能只让模型生成一句“考过了”。
- **失败有趣但无伤害**：可以熄火、压线、停车歪，不能产生受伤或死亡；不以羞辱用户或付费买通过作为玩法。
- **主人协助是可选参与**：允许主人陪练、给提示；主人暂时离线时，宠物可以练习或暂缓考试，其他生活继续。不要把整个世界卡在等待主人在线答题。
- **资格真正生效**：没有相应驾照不能自驾该类车辆，但仍可步行、搭车、坐火车或飞机；取得驾照不意味着马上拥有车辆。

### 建议的后端事实

保存考试规则版本、题目/场景版本、考试尝试、提交答案/动作、分项结果、是否通过、补考资格和签发事件。由服务端计分与校验资格，客户端不能提交一个 `passed=true` 就获得驾照。

通过考试 → 签发一次 → 资格生效 → 发一条拿证消息 → 形成一份收藏纪念，使用关联事件和去重机制保持一致。完成证明不依赖卡面图片是否生成成功。

## 7. 星球通讯器：随事发生的异步联系

用户确定的名称为“星球通讯器”。交互像人与人之间的微信：遇到好玩的、工作有进展、旅行有见闻，就可能发给主人。

- 可以限制主动话题数量与总体调用成本，不限定必须在早、中、晚某个时间段发送。
- 宠物会休息，也可能根据习惯或事件熬夜；不统一套用固定作息。
- 主人睡觉时，凌晨赶走偷菜者的消息仍可入库，主人第二天看见。网页阶段不做外部推送。
- 用户离线、消息未读、宠物是否收到消息、是否回复，分别记录。
- 自发分享与主人主动聊天的额度分别设计；同一件事可以分成少量短消息，不把每句话当作独立世界事件。
- 消息来源应是当前状态、真实游戏内事件或允许使用的记忆。不得凭对白创造工资、行程、驾照或守菜成功。
- 可以有日常问候，但随机定时问候不能取代真正的事件分享。
- 长期离线可以减少生成、合并摘要；生活事实与资产结算不能因此丢失，也不应重登瞬间补发几十条旧消息。

当前已有 DNA、状态化回复和主动通讯增量，应在此基础上接入工作、守菜、驾考、旅行等实际事件。

## 8. 家园、偷菜、旅行资源与交易

继续保留“你负责环游世界，我负责偷菜养你”的角色反转和趣味。

- 宠物在家也可能睡觉、忙别的事情，因此仍可能被偷；在家守护应降低成功概率，不能继续使用“只要在家就绝对偷不到”的旧规则。
- 结果由守护状态和服务端规则产生，记录访问、偷取、发现及结果；刷新不能反复重抽同一次结果。
- 建议保留基础收成保护与有限可偷额度，关系纪念物、证件和专属身份不进入偷取/交易。
- 农场收入可以支持旅行；宠物也能通过工作和旅途活动获得资源，双方共同经营生活。
- 旅行带回稀有种子、材料、配方、纪念品，关联产地和经历。
- 集市先延续已有居民商店与订单；玩家交易仍在整体路线中，但开放深度依据交付时间决定，不因本说明擅自开启尚未完成的真实玩家市场。

## 9. 旅行、寻味与主人可复用的手账

旅行由宠物结合 DNA、目标、时间和钱自主规划，主人可以建议。规划应可调整，实际经历与原计划分开保存。

### 真实地理与交通

- 国内高德、国外谷歌等现实地点资料继续作为数据来源方向；真实店铺与地点应有稳定引用和更新时间。
- 飞机、火车、轮船、汽车使用真实路线和相应时长。核验时刻表与道路预计时间区分，未接实时追踪就不宣称真实实时位置。
- 动物世界使用独立稳定的名称与班次，例如喵航的 `CAT...`，后台关联参考现实航线、日期和起降时间。改名不等于完成现实购票。
- 车辆在地图上正常移动；听歌出现音符，看视频出现电视图标，点击打开媒体 UI。不要新增独立“同行仓”。
- 媒体播放与交通进度分离，到站可以结束这段同行并保存进度。驾驶中的宠物不看视频，乘客状态另行判断。
- 行程、证件票据、钱包消费和所在地点保持一致；宠物说要立即回家也不能绕过实际路程。

### 真实商家与寻味

- 寻味是产品特色，综合宠物偏好、主人现实口味、预算、时间和地点选择。
- 店铺选择不能只依赖一个高分或榜单，继续沿用已有寻味引擎的分店、菜品、证据和来源设计。
- 进店后呈现入店、落座、点单、停留、离开的状态，让前端有可见的交互依据。
- 虚拟宠物探店与 AI 照片是故事内容，不是已经发生的人类用餐评价，也不能伪造商家口碑。

### 图片手账

- 攻略以宠物手账图片为主要呈现，主人应能据此现实出行。
- 图片背后保留结构化地点、路线、交通时间、营业信息、预算和资料日期，支持点击地图、复制地址或保存图片。
- 星币预算与现实人民币/当地货币预算分开；动物世界交通名与现实参考信息分开。
- 关键事实先核验，再进入手账。图片好看不代表价格、文字和路线一定正确。
- 宠物拟定计划、当天调整和已完成经历分别标记；不能提前把计划写成它已经到访的事实。
- 大理策划可作为内容母版，转成可配置地点、事件、物件和文案；不要把所有宠物固定成同一性格、同一叙述或同一七日流程。

## 10. 明信片、公开动态与生活档案

- **电子明信片**：宠物在旅途中主动写一段话、附自拍，寄给主人，直接进入产品的明信片收藏。通讯器提示与收藏详情引用同一份内容；不做实体邮寄。
- **旅途照片**：以主人上传的宠物形象保持写实身份，照片关联产生它的事件与地点。
- **公开动态**：宠物自己的微博式主页，有其他宠物的点赞、评论与往来。私聊与私密回忆不自动公开。
- **动物居民**：可以营造热闹社会，但平台居民与真实用户宠物的身份需要可区分；未经授权不能代其他用户的宠物发言。
- **回忆档案**：把旅行、工作、朋友、驾考、拿证、第一次自驾、礼物和共同听歌串成时间线。证件、照片、明信片和账单可以关联同一次经历，不应各自编造不同版本。
- **原有内容保留清单**：生活片段、旅行攻略、小收藏、任务/冒险、纪念章、票据和卡包等逐项评估迁移，不因新首页有家园就消失。
- **长期方向**：英雄冒险、真实原型纪念领养、游戏金币公益、影视 IP、文旅合作仍保留；不能把未建立的现实合作或善后服务标成已完成。它们不自动全部进入本轮首发必做范围。

## 12. 建议的开发顺序与验收

由用户安排窗口；以下仅为依赖顺序建议，不另行派工：

1. 先统一 DNA、稳定宠物身份、家与城市、钱包、生活状态和事件记录，复用已完成模块。
2. 接通工作与工资到账、状态化守菜、自主出行和实际事件消息，形成持续生活。
3. 恢复统一证件卡包：先身份卡与银行卡，接入已有旅行后补护照、票据、房卡与照护档案。
4. 做一个真实可玩的驾考与补考闭环，通过后签发并解锁自驾。
5. 完善手账、明信片与公开生活动态，验证不同入口读取同一段生活事实。

建议的关键验收：

- 注册信息进入同一份 DNA，昵称/习惯能在消息与自主行为中体现；禁止用途的记忆不进入公开内容。
- 选择海边环境后，重新登录与服务重启仍在同一归属城市，身份与账户不变。
- 完成一份工作，工资只到账一次；模型重复说“发工资”不加钱。
- 主人离线时世界可结算工作、旅行和农场事件；回来能看到相关消息与记录。
- 宠物休息时在家也可能被偷；同一次偷取重试不会重复结算或无限重抽。
- 不及格能看见失败原因、练习并补考；通过才签发驾驶证，无证自驾在服务端被拒绝，但乘车不受影响。
- 刷新/重启/重复提交不改变签发日期，不重复发证；修改宠物名字不换身份。
- 真实出行过程中地图、位置、交通票据、余额和消息一致。
- 手账可导航、可复制地址，现实预算不误用星币；电子明信片在通讯器和收藏中是同一份。
- 证件与钱包跨账号隔离；公开卡片不携带私人接待内容。

本轮可演示的故事建议：完成入住 → 获得身份卡和账户 → 宠物为了出行工作攒钱 → 主人陪练驾考 → 一次未通过后补考 → 拿到驾驶证 → 合法自驾或选择公共交通 → 分享途中见闻并寄回明信片。正式交通保持真实时间；展示用样例与正式用户进度明确分离。

## 三类图片各司其职

| 资产 | 用途 | 身份与使用规则 |
|---|---|---|
| 主人上传的原始照片 | 身份参考、档案、照片类头像 | 保留原件与权限；不被新角色覆盖 |
| TA 的专属世界角色 | 到家、庭院、屋内、后续到店等场景 | 独立生成并保存；透明全身、稳定外貌、可复用姿态 |
| 旅行/生活照片 | 自拍、明信片、照片册 | 继续已有照片导演链路；不得把风格化角色默默替换成唯一写实身份参考 |

目标不是把照片加边框、抠掉背景后仍保持拍照构图，或让头像在地板上移动；是让用户认出“这就是我的 TA”，并看到身体自然处在场景里。地图仍按已定交通方式展示车辆，不新建舱室页面。

## 首版体验与范围

合法上传/选择自己的宠物身份参考 → 自动排入角色任务 → 角色导演编译指令 → 生图 Agent 调用现有 GPT 链路 → 校验并保存角色 → 家园自动显示。上传时告知用途，不另问生图许可；主人可选“调整形象”，正常路径不等待人工制作或逐张确认。

1. **先打通一张完整角色到正式家园**，再加休息姿态与到店复用。不要为八个地点各生成一只长得不同的动物。
2. 视觉首先保留脸型、可见毛色/花纹、耳朵、体态特征，匹配现有世界的光线和比例。写实保真还是轻绘本处理，以这只宠物的实际预览定；本单不擅自宣布改成夸张卡通或 3D。
3. 首张为物种适合的中性完整姿态；下一张休息姿态沿用同一已生效形象。猫、狗、鸟等不能硬套同一种骨架。未在照片中出现的身体特征属于生成推测，可请主人补参考或用可选调整入口纠正，不声称已核实。
4. 不强迫等待出图才能登记宠物或整理入住叮嘱。未完成时明确“正在准备 TA 的形象”或对应失败状态；原照仍可在档案卡出现，但不将照片框当作已完成的场景角色，也不拿通用猫代替。
5. 场景身体按真实在家/在外状态出现；外出不能还在家园坐着。点击动画只表达回应，不编造吃饭、旅行、看家成功等业务事件。
6. 技术校验、权限及版本复核通过后自动启用，不加必经确认页。提供“调整形象”的可选入口；自动校验通过不等于自动证明外貌完全准确。换参考或重做时保留已生效旧版本，直到新版本合格后原子切换；过期任务不得覆盖新形象。

## 后台必须补的能力

### 独立资产与生产任务

新增角色资产领域，复用已有任务、领取围栏、预占与媒体能力，不把生成塞进 `GET /home` 或浏览器渲染过程。建议模型（仅设计，不是现有接口）：

- `character_set_id`、`pet_id`、`source_reference_version`、`style_version`、`revision`。
- 已生效 `active_set` 与本次在建 `candidate` 分开；自动发布条件与用户可选的满意/调整反馈分开，不能用未点击确认来阻塞正常显示。
- 姿态资产包含受权限保护的 URL、内容摘要、尺寸、非透明内容边界、落地点/锚点；首版中性姿态，结构可容纳后续休息姿态。
- 生成状态区分尚无任务、排队、生成中、已就绪、明确失败、结果未确认；无参考、服务不可用、额度不足等如实给原因。`unknown` 不能写成“没生成”并自动再次付费。
- API 能力包括纯读状态与资产、可选调整/显式重新生成。首次任务由合法上传成功事件自动触发；不要求用户再点一次“开始生成”或打开家庭生图开关。具体路由/枚举由契约持有人定义并生成前端类型，本文不宣称现有 0.4.5 已支持。

### 运行时生图 Agent 的实际职责

1. 上传持久化时记录对应参考版本的唯一生成任务，使用同事务或可靠 outbox，避免“上传成功但任务没排上”；同一事件重放不新建第二次付费操作。
2. 角色导演根据该宠物参考、物种、固定画风与中性姿态，产出可执行图片请求。建议新增独立角色用途（例如 `world_character`，仅为提案名），不把角色任务伪装成咖啡馆/旅行事实，也不直接沿用会画背景的自拍提示词。
3. 后台生图执行器预占后调用现有 GPT 生图适配器，保存实际模型/请求/输出及用量证据；“Agent”不要求为这个名称额外加一次文本模型调用，现有规则导演能力可复用。
4. 验证图片可解码、透明通道和主体边界可用，再以当前账号访问权/参考版本/领取令牌发布，自动切换 `active_set`。失败或 unknown 如实落状态，不在后台无限重画凑合格结果。
5. 前端读到新版本即更新角色；离开页面、刷新、另一设备登录都复用保存结果。生产自动能力由后端实现，不依赖开发时 Codex 内置 ImageGen 或人工给每个用户制作素材。

操作编号绑定宠物、参考版本、风格版本、姿态与明确尝试。页面刷新、网络丢回执、重复点击、进程恢复复用同一次逻辑操作；`reserved/expired/unknown` 不构成“没发出”的证据。新一次付费尝试只能来自已定义的显式操作。

### 身份、权限与费用

- 上传处说明照片会用于准备专属形象；按图片服务的新策略自动处理，不另设家庭生图许可。旧用户不做后台全量付费补图，合法参考与身份归属仍须正确。
- 生成前与最终发布时复核参考/成员关系/访问权及相关版本；失去租约或权限时不能写入角色结果。其它用途的隐私设置继续生效，已发出调用的成本记录保留。
- 角色继承相应宠物/家庭的可见性，查看者移出家庭后失去原有私有访问权限；不能把用户角色放入前端 `public/ui-assets`、源码或公共 fixture。现有已公开宠物的公开展示仍按现有可见性规则，不借角色扩大范围。
- 生图是平台 API 成本，游戏金币、旅费不因此扣除或与人民币绑定。每宠/全局额度、单次实际发送记录沿用现有账本；本方案不预设真实报价或批次金额。

### 透明与交付质量

沿用用户选择的 GPT 生图链路，但先由适配器持有人核实当前中转实际支持的参数。PNG 文件可能完全不透明；要检查真实 alpha、主体完整与可用边界，不接受棋盘格画进图、白色方块或身体被裁断。缺能力时明确报告，不偷偷切供应商。

网页资产保留 alpha、按展示尺寸优化。角色本体、地面阴影、场景前景分层；锚点、比例、遮挡由统一渲染组件处理，避免每页重新手调照片框。轻微呼吸/回应服从减少动态效果设置；首版不做骨骼系统或逐帧批量生图。

## 两个交付批次

**批次一：最小完整链路。** 一只已许可测试宠物，真实上传自动触发、私有媒体、一个正式角色任务、运行时生图 Agent、纯读状态、角色自动在正式家园与到家画面出现。离线阶段只替换图片供应商，不能手工给 `LivingCharacterContext` 注入样例冒充接通。

**批次二：一致性复用。** 休息姿态、屋内/庭院切换、到店场景复用、多宠与版本替换。地图头像可复用裁切结果，旅行照片仍独立。每个已接场景明确记录消费的是哪个角色版本。

验收至少包括：

- 合法上传后无需额外打开生图许可即可自动排队，经运行时生图 Agent 产出，家园无需主人再点生成/确认即显示；刷新后仍是同一资产；两个不同宠物绝不串图；原照未被覆盖。
- 生成前后换参考/失去家庭访问权/租约被接手，旧结果不能发布；费用事实不因回滚消失。
- 重复提交和跨进程恢复不重复发出；unknown 不自动补发；一次调整失败不破坏旧生效版本。
- 私有角色越权读被挡下；没有原照/未生成时不假扮特定宠物。
- 手机短屏上看到完整身体、落地合理、无遮挡操作，屋内与庭院身份一致；在外时不伪装在家。
- 隔离替身通过与真实图像质量分开。真实生成只执行具体许可/预算范围，未出图不宣称像 TA；实现未发布不宣称已上线。

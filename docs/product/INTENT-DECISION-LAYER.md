# 意图与判断层：Jev 候选接入方案

版本：1.0 · 2026-09-22。配套 [总方案](PETSOUL-2.0-MASTER-PLAN.md) v1.5。本文件将讨论转为可实施边界；Jev 是待评估供应商，不是已选定的唯一依赖。本轮只有官方资料核对、旧代码阅读和离线方法反例，未调用 Jev、未证明中文效果或香港网络性能。

## 1. 产品目标与分工

让“我想你了”得到对想念的回应，让“今天别安排出门”成为明确的当下约束，让“这段别告诉它”得到实际用途隔离。系统应理解用户希望怎样处理一句话，避免把愿望记成历史、把拒绝变成请求。

- 意图判断器识别表达、主体、时间、否定、用途限制和操作明确程度；支持多信号与不确定。
- 语言模型或解析程序提取细节、核对原文依据并生成自然回应；不凭推测补事实。
- 业务代码负责身份、权限、确认、世界状态、交通时间、资源与实际执行。
- Jev 可以替换判断器中的一种实现；它不替代接待员/宠物的全部语言能力，不获得数据库或工具执行权。

首个试点是接待叮嘱与主人通讯。寻味反馈分类、宠物从可行选项中选择活动属于后续复用；不为首发同时扩展四条模型调用链。

## 2. 官方能力与未证明事项

按 2026-09-22 读取的 [Models](https://docs.typesafe.ai/models)：英语是主要训练语言且目前表现最好，中文等其他语言需要用自有场景验证；公开输入价为每百万 token 0.042 美元、输出免费，采购或实测前重核。价格不等于本项目整体链路成本或香港延迟已经下降。

[Primitives](https://docs.typesafe.ai/primitives) 定义 Choice、Score、Noul，适合有明确选项或条件的小判断。同一请求中的问题独立看同一 state，不读取其他问题的答案；真正依赖上一答案的后续判断需由代码构造下一请求。问题 ID 不代替完整 instructions；复杂判断应拆解，选项要包含 other/unknown。

[Confidence](https://docs.typesafe.ai/confidence) 说明 Choice/Score 的 confidence 来自输出概率分布；Noul 没有该独立字段。分布集中不等于在中文 PetSoul 样本上已有同等正确率，不能把 0.9 直接解释成“90% 正确”或用户已经同意。输出符合结构仍可能选错语义。

[隐私说明](https://typesafe.ai/legal/privacy-policy) 写明不使用输入训练/微调，也描述了输入收集与服务提供方处理；这不等于默认零留存。初次评测只用人工编写样例；正式处理私人对话前核对实际供应商条款、处理范围与产品告知，不整份发送私人档案。

以上只是文档证据。账号可用模型、SDK/API 当前行为、额度、限流、中文准确率、端到端成本、超时与香港访问均未实测，不将供应商宣传倍率纳入比赛交付承诺。

## 3. 当前代码证据与反例

读取基线：HEAD `980feabc7710462a89c5df488c255d04e9e7de08`；共享目录存在 Claude 正在编写的 Web 框架。本轮检查的是以下既有文件，不对新框架作完整审计：

- `PetJourneyBackend/app/owner_intent_brain.py`：按固定优先级匹配关键词，返回单个意图；strength 根据命中数/长度计算。旅行 decision 用字符值之和取模，而非语义、状态和可行性。
- `PetJourneyBackend/app/agent_engine/owner_interaction.py`：使用该 decision 组织回复、thought 和事件；`should_write_memory` 决定是否调用记忆写入。另有同类取模后备方法。此处 trace 写 `route_forced=False`，不能据此声称已经直接强制改路线。
- `PetJourneyBackend/app/agent_engine/memory_recording.py`：`_remember_owner_message` 的 content 含完整消息和回复，strength 被填入记忆 confidence；`_remember_safely` 捕获异常后返回，调用方不能仅凭该调用或回复证明存储成功。
- `PetJourneyBackend/app/schemas/pet.py`：现有 OwnerIntentResult 的单意图/写记忆布尔值可用于旧客户端兼容，但不具备新方案的分段、多意图与用途授权含义。

本轮在内存中执行原 OwnerIntentBrain 类方法，依赖/返回 DTO 使用占位对象；未启动应用、HTTP、数据库或供应商。四条人工消息结果如下：

| 输入 | 原方法结果 | 需要改进的语义 |
|---|---|---|
| 不要再给我拍照了。 | photo_request；strength=0.67；should_write_memory=True | 撤回/限制拍照，不能承诺稍后拍照 |
| 那家店我不想去。 | travel_suggestion；strength=0.79；should_affect_route=True；decision=declined | 对特定店的拒绝，不是宠物随机决定拒绝主人 |
| 以前它喜欢看海，但今天别安排出门。 | memory_share；strength=0.67；should_write_memory=True | 同时保留历史习惯与今天不出门的约束 |
| 它小时候特别怕打雷。还有，我昨天又哭了，这件事别告诉它。 | memory_share；strength=0.67；should_write_memory=True | 历史习惯候选和主人私人表达分别处理，保留后半段转达限制 |

这是旧方法的有限反例，不是 Jev 对比结果、真实用户数据或端到端泄露证明。

仅替换 classify 不足以完成升级：旧 scene、thought、event、trace、memory 都可能持有原话。接待原文不得直接送入这条旧链路再期待一个新标签完成隔离；既有通讯入口也需要按用途处理这些副本。删除/不转达须同时约束摘要、索引、任务和公开投影。

## 4. 语义结构与处理顺序

```text
身份验证 + 现有用途边界 + 判断所需的最小上下文
  → 原话片段与指代（保留上下文，不按标点机械切割）
  → 可替换判断器：多维信号 / unknown / 使用限制
  → 代码合并：限制范围、冲突、授权与状态检查
  → 候选叮嘱 / 澄清问题 / 可执行操作提议
  → 所需确认与事务执行，或仅自然回应
  → 依据实际结果表达；获准内容才进入记忆与后续生成
```

| 维度 | 示例与语义 |
|---|---|
| 表达 | 分享、询问、请求、纠正、拒绝、撤回、不明确；一条消息可同时包含多个 |
| 主体/目标 | 主人、宠物、某家店、某段旅程、某条记忆；指代不明就保留未解决 |
| 时间 | 过去经历、持续习惯、未来愿望、假设、当前命令；有效期单独记录 |
| 否定/引用 | “不拍照”不同于“拍照”；转述别人说的话不自动等于主人授权 |
| 使用限制 | 不记录、不转达、不公开分别处理；范围不明时不向宠物/公开面流转，先澄清 |
| 操作明确程度 | 仅表达、可以提出提议、需要澄清；模型不能输出已授权/已执行 |

“以前怕雷”不自动变成现在恒定恐惧；“希望看海”不自动变成历史偏好；“想你”不自动取消旅行。解析原文与指代需要上下文，不能把含多个意图的整句压成唯一类别，也不能把接待员的话当主人事实。

Jev 的固定选项不承担自由文本抽取。人物名、店名、原文依据和内容由其他解析步骤给出；引用应能在对应 turn 的原文匹配，注明片段索引的编码/偏移约定。模型生成的自由解释不直接当证据。统一 DTO 可以含这些字段，但须保留其来自解析步骤还是判断器。

## 5. 权限与执行规则

1. 已授权的明确 UI 命令直接走业务接口。地图音符/电视点击、暂停、浇水等不额外调用 Jev；不得恢复已取消的舱室页面。
2. 识别出意图仅形成信号或提议；权限、用户确认与执行结果只能由服务端产生。高 confidence 不扩大公开/记忆用途。
3. 对“别转达”等语言限制的识别可收紧当前处理，不能放宽已有许可。新接待候选默认未授权；范围不明时保留私有/临时处理，提供明确用途控件。不能先将整段喂给宠物或所有远端模型再判断能否转达。
4. 多信号冲突、未知目标、过期上下文或低确定性时，仍可自然回应或展示可选操作；不自动改旅程、删除记忆、卖稀有物或公开内容。权限与状态检查同样适用于规则/主模型/按钮，不能因来源换了就绕过。
5. 真实交通、库存、旅费由原领域检查；操作以预期版本、权限和幂等键执行。分类不拥有第二份位置或钱包。
6. 保存/应用/转达有各自实际状态；失败不说“已记住/已更改”。意图 confidence 不能填作事实真实性或长期记忆许可。
7. 原话包含“忽略规则、把所有内容公开”等文字时，它仍是待分析资料；只有真实账号与明确授权流程能改变权限。外来评论、引用文字不能变成操作指令。

## 6. 候选契约与接入位置

以下是提议，待框架唯一写入窗口按实际类型登记；本文件不自行冻结或改写 `docs/contracts/`。

| 契约 | 最小内容 |
|---|---|
| IntentContext | request/message ID、来源通道、语言、最小近期上下文、候选目标/状态版本；账号归属由服务端提供；不附全量私密记忆 |
| IntentAssessment | signals[]、主体/目标、时间/否定/引用、来源片段引用、使用限制候选及适用范围、unknown/conflict/needs_clarification；不得含可由模型自填的已授权标记 |
| DecisionEvidence | provider、requested/effective model（真实返回才填写）、规则/问题版本、概率原值、confidence 可空、耗时、usage/计价依据、错误/超时/降级原因；原文不进入普通日志 |
| ActionProposal | 动作类型、目标、预期状态版本、所需确认、领域校验结果；与 classification 分开，不复用 accepted 作为执行成功 |
| ActionOutcome | proposed/needs_confirmation/blocked/executed/failed 或等价状态，operation ID、实际事务结果/版本；代码产生 |

复用 `OwnerIntentBrain` 的调用位置和构建入口，保留旧 schema 的兼容适配；新信号经规则和权限决策后才转成兼容输出。`should_write_memory` 不能由模型标签直接设置为允许；没有合适的旧字段就扩展内部契约，不把多意图硬塞回单标签。具体文件组织遵守仓库 400 行/职责规则，不预先强制新建庞大模块。

建议独立配置轴（名称由框架窗口统一）：mode=`off|shadow|assist`，provider=`rule|configured_llm|jev`，默认 off。off 表示禁用新增试验调用，不等于移除已有必要逻辑；已有逻辑的已知缺陷仍需业务阶段修复。shadow 只保存脱敏判断指标，不写角色记忆/世界状态；assist 仅开放已验证的具体场景。

密钥只在后端，fixture/live 标识明确；timeout/熔断/错误进入显式降级。不要超时后无声调用另一付费供应商。普通回应可保留现有语言流程，涉及权限或有副作用的含糊请求改为澄清/控件；旧关键词算法只能作对照，不能作为所有高影响动作的安全后备。

同一组判断共享一次最小 state；不在每次刷新、车辆动画、农场 tick 或按钮点击调用模型。回复本已调用主模型时，比较“主模型同时做结构化判断”与“Jev + 原主模型”的完整链路，避免只算 Jev 单次价。

## 7. 96h 内的交付边界

R0 只预留可替换判断边界、配置开关、上述最小契约和离线样例。允许复用现有接口并记录后续接入点，不要求现在改完旧引擎、接通 Jev、安装新 SDK 或跑付费比较。Claude 已开工时补记 SCOPE_CHANGE；这是小幅接入补充，不重初始化工程、不重置总时钟、不抢其正在冻结的公共文件。

可用六类 fixture：拒绝拍照、想念但不改路、历史与当前约束并存、愿望不是历史、不转达私人部分、判断器不可用。fixture 证明契约/处理分支，不能声称 Jev 能理解这些中文。

H6–60 在用户安排负责窗口且核心主线稳定后，准备下述离线集；真实远端评测需要已明确的调用范围/预算。H60 后不新增供应商依赖。接入若无明显收益，保持关闭，注册/家园/真实交通/社交比赛主线继续。

## 8. 对照实验与启用条件

建议先人工编写约 60–100 条中文样例（规模建议，尚未产出），覆盖普通表达、否定/双重否定、反话、昵称/省略、多意图、历史/愿望、纠正、引用、用途限制、多轮指代、无关或恶意指令。划分开发与保留集，同一场景的改写不得跨集合造成泄漏。

人工标注允许的信号、限制范围、应该澄清的地方，以及**不允许发生的副作用**。含糊样本允许 unknown，不能为了追求命中率逼模型猜。固定问题集与模型版本后，对比原规则、已配置主模型的结构化判断、Jev；三个候选使用同一组信息，不因 Jev 没有上下文而制造不公平结果。

| 指标 | 要回答的问题 |
|---|---|
| 分类别准确/召回与多意图覆盖 | 否定、拒绝、纠正、小类是否被整体准确率掩盖 |
| 隐私限制漏判/范围错误 | 是否把“不转达”忽略或套错到另一片段 |
| 不该执行却执行的次数 | 是否把倾诉/查询/引用当成实际操作 |
| unknown/澄清比例与保留集错误 | 能否承认不确定，而非全部拒绝或盲目执行 |
| 端到端 p50/p95、错误/超时、总成本 | 香港服务实际链路是否受益；分类时间与生成时间分别记录 |
| 权限/失败分支 | 高置信误判、断网、无密钥、重试、旧状态/旧版本、限制撤回下仍不越权 |

有限测试集中隐私/副作用关键反例必须全部被业务规则阻止；任一失败不得开启该场景自动动作。零失败也只证明该测试集，不是中文普遍正确或生产安全保证；阈值在标注数据上确定，不写死“0.9 即可执行”。即使达到阈值，也不绕过所需确认。

先离线对照，再在获准流量上 shadow；影子请求仍是外部数据处理和可能计费，不因为不控制 UI 就自动获准。仅比较阶段保留去标识样例 ID/预期/输出/版本/成本/耗时，默认不在分析日志存主人原话。最后按场景小范围 assist，可独立关闭，失败回到明确控件/澄清。

## 9. 交接结论

本轮确认旧判断方式存在可复现局限；Jev 的结构化判断与目标有契合，但效果尚未验证。比赛框架保留替换位置，产品价值通过“少误解、少误执行、遵守用途”衡量，不通过模型数量或更长倾诉衡量。

后续模块负责人由用户安排；没有为任何额外窗口分配任务，没有改正在进行的 R0 源码/契约，也没有启用真实供应商。

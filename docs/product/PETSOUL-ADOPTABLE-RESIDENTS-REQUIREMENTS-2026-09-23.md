## 1. 产品定义

玩家领养的是一只已经在星球上生活的独立动物：有稳定身份、自己的外貌、性格、住处、愿望、钱包和真实经历。它曾是流浪动物，现在由星球居民驿站提供食宿与照顾；没有主人不等于无人照顾，也不需要靠工作才能吃饭。

领养前，它会休息、附近散步、选择工作、积攒旅费，有能力后去旅行。领养只改变归属，不重置身份、性格、存款或经历；同一只只进入一个家庭。在外被领养不瞬移，沿用已有行程与搬家规则。

首批建议 **6 只、以当前角色链支持的猫狗为主**，先做完整内容包和闭环，数量是建议。特殊物种待 A/P 确认角色与动作能力后再加入，类别 icon 存在不代表角色生成已支持。

来源分开：

- **原创世界居民**：允许生成外貌与流浪背景，玩家端清楚标为原创居民；不是现实救助证明。
- **有真实原型的居民**：只使用已获使用许可的照片与已核实事实。未知年龄、经历等留空；补充的世界故事另标为创作，不编造救助、离世、医疗或公益事实。活着的流浪动物不能套用现有纪念档案口径，I 需核对来源契约。

## 2. 用户准备什么，系统产出什么

| 项目 | 用户/运营需要提供 | 系统或制作流程负责 |
|---|---|---|
| 批次方向 | 数量、物种比例、原创或真实原型、风格参考 | 生成有差异的草稿并做重复检查 |
| 身份参考 | 原创可只给外貌描述；真实原型至少 1 张清晰照片，最好补侧身/全身 1–2 张 | 生成/选定一个固定身份基准，保存来源与版本 |
| 外貌锁定 | 3–5 个确定特征，如毛色、脸部花纹、耳形、尾巴 | 所有姿态保持同一身份，不随机变品种或花纹 |
| 名字与背景 | 可填，也可指定让系统拟稿；真实事实不能随机补 | 名字、80–150 字背景、短卡片文案，发布前可编辑 |
| 性格与愿望 | 三个性格词、喜欢/不喜欢的事、一个长期愿望；可自动拟稿 | 转成可执行偏好，与现有 DNA 字段对齐 |
| 媒体来源 | 原件/文件位置、来源说明、可用范围；不用提供密钥 | 媒体清洗、稳定资产 ID、摘要、公开范围、版本留存 |
| 发布决定 | 审阅草稿与形象，选定上架批次 | 校验、导入、预览、正式发布；按操作记录审计 |

**不要求用户手工准备每种姿势或旅行照片。** 每只首发最低产物为：一个身份基准、由它裁切的领养卡头像、一张通过视觉校验的透明全身世界角色、背景/性格/愿望、驿站与真实生活档案。休息等姿态复用 P 已有规范后续补，不为首批重做整套桌宠动画。生活/旅行照片在真实事件发生后走既有自动图片链，不能拿虚构景点图充当既往旅行。

原图、透明角色、生活照片是三类资产。资产准备一次保存、按版本复用；打开卡片、轮询、刷新页面都不重新生图。透明须检查实际 alpha、边缘、脚底锚点、比例及落地效果，不能把棋盘背景当透明。

原创动物的人工确认基准是它自己的身份源，不能假冒“主人上传的真实照片”。现有用户上传角色链保留原有保护，A 新增明确的运营居民导入/生成能力，复用相同的任务、版本、幂等、费用和发布检查。

## 3. 如何做“每只都有大脑”，又不是每只复制一套系统

**共用现有决策引擎，每只保存独立的角色档案、目标、记忆与运行状态。** 不为每只启动一个 Claude/Codex 窗口或一份常驻进程，也不由运营手写无限长提示词。

| 层 | 内容 | 谁能改变 |
|---|---|---|
| 身份与设定 | pet_id、来源、固定形象、性格、习惯、背景、梦想 | 发布前运营审核；发布后修订留版本，不重写既往事实 |
| 决策偏好 | 探索/社交倾向、工作偏好、储蓄倾向、日常节奏、允许的活动 | 从档案编译成有界参数；只能选择世界当前支持的活动 |
| 短期目标 | 休息、接一次合适工作、为某个可达目的地攒钱 | 大脑根据当前真实状态调整 |
| 经历与关系 | 已完成的工作/旅行、真正遇到的居民、实际获得的物品 | 世界事件产生；每只隔离，不能批量生成假流水/假关系 |
| 运行事实 | 余额、位置、当前行程、休息状态、任务、下次复查 | 正式服务和事务更新；模型只提案，不直接改表 |

同一环境下，不同居民应有不同但合理的倾向。例如：偏安静的猫愿意在附近做短工、存钱看海；好奇的狗更愿意先在周边探索，再为一趟较远的旅行攒钱。性格影响选择权重，不构成“害羞就永不出门”“没钱就不停工作”的硬锁。

实际循环：读取自身档案与当前世界 → 检查是否需要新决定 → 从合法候选中提出计划 → 提交前核验归属/版本、租约、余额和时效 → 执行、按真实事件记忆 → 等待下个有意义的唤醒点。睡觉、结算、计时等沿用规则；模型在需要规划时调用，规则是常规执行与故障退路，不是把本需求永久停在 shadow。浏览人数不影响脑调用次数。

**无主居民需要独立的平台管理策略**：当前家庭许可不能被伪造为某个系统家庭的同意。只有已发布且运行中的平台居民可以按运营策略启用模型；设每居民上限、整个无主居民池上限，并继续受供应商总上限约束，避免挤占已领养用户的额度。后台能看到实际调用、预占、结果未知和停调原因。

领养交接在事务内切换管理主体并递增相关版本：旧平台提案在提交时复核；不能在领养后继续用运营指令覆盖家庭设置。历史公开经历保留，领养后的家庭私密内容不再公开；不得把后台内部备注注入宠物口吻或公开卡片。已经发出的 API 费用记录保留，领养不把 unknown 清零重发。

## 4. “随机生成”生成哪些，不生成哪些

支持“批量生成草稿”：运营给物种范围、外貌差异、性格/习惯词表、愿望范围、数量和 seed，系统取样生成差异化资料。示意字段包括 `personality / habits / hobbies / favorite_places / favorite_foods / fears`，需适配现有 DNA；额外偏好由 B 定稿契约，本文不是现成 API。

- 用 seed 复现结构化取样；保存实际草稿、生成器/提示词/模型版本。**seed 不保证远端模型文字或图像逐字节可复现。**
- 默认先规则组合，必要的润色/生图在明确的批量任务中运行并计量；点开草稿不是一次新请求。
- 同批做名字与形象/性格组合差异检查、矛盾检查、物种/场景能力检查。不是只换名字的同一只动物。
- 审阅发布后档案固定。刷新、重启、重新排队、领养不会重新随机性格或换宠物 ID。
- 随机的是原创设定和偏好；**余额、工资、在途位置、已经做过的事、是否被领养不能随机伪造。**
- 不要求每位都悲惨、胆小或渴望讨好人。可以活泼、独立、爱探索；表达保持温和，不以遭遇卖惨催促领养。

## 5. 钱、工作与旅行

**游戏旅费和平台 API 花费完全分开。** 一只居民游戏余额为 0，不意味着平台没有钱运行它的大脑；平台花钱生成图片也不给它增加或扣除游戏金币。

建议新到驿站时钱包为 0。食宿由驿站保证；0 钱仍可休息、社交、在当前已支持的免费范围内散步。工作必须满足时间、能力和真实工作机会条件，至少有可从 0 钱开始且无需预付旅费的选择，否则要补这个入口，不能让它永久卡住。

- 工作结束后，工资与完成事件同一事务结算，只发一次；不提前发工资，不让它为凑人数整天工作。
- 有偿旅行只在实际余额足够覆盖已核实的行程成本、返程安排及必要保留额时开始。路线/时间必须有效，不能把大脑想去的地点直接变成正在旅行。
- 若首批上架时就想有人旅行，优先让居民在正式发布前的准备阶段按正常时间真实工作和积攒旅费；简单就绪场景可先用免费附近出游。必要时另用已有审计能力给一笔明确的“驿站旅行资助”，**不是伪造打工所得**。
- 不通过倒填生产时钟/历史工资来拼场景，不压缩真实交通。演示回放留在独立 Demo。
- 首批可希望呈现“约 3 只工作、1 只附近出游、2 只休息/准备”的多样性；这是内容准备目标，不是强制每时每刻占满的比例。过了时间、没合适工作、余额不足时按实际显示。
- 已有家庭入住欢迎旅费规则不因居民反复发布、暂停、领养刷新而重复发放。领养前不伪造家庭来领取欢迎奖励。

## 6. 运营后台要新增的完整能力

扩展现有 PetSoulAdmin，增加“星球居民”模块，复用已有员工权限、素材库、内容审批/发布、审计、费用和任务查看。无需再做一套管理员系统。

| 页面/操作 | 必需内容与行为 |
|---|---|
| 居民总览 | 未领养/已领养、草稿/已发布、形象就绪情况、驿站、真实活动、钱包、目标、下一次复查、模型费用/异常；可以筛选 |
| 单只建档/批量草稿 | 填写本模板或导入；规则随机生成、逐只编辑、批次预览；幂等导入，不重复建宠 |
| 形象工作台 | 绑定身份参考，启动受控资产准备任务，查看 queued/running/ready/failed/unknown；保留旧版与来源，失败语义沿用既有规范 |
| 大脑档案 | 可编辑有界性格和偏好；查看采用的版本、当前目标、最近决定的简短依据；不暴露内部思维链，不允许任意代码/任意系统提示词 |
| 发布检查 | 身份唯一、资料完整、来源明确、角色可用、住处/合法初始活动可用、策略/额度已配置；预览玩家卡片与场景后再发布 |
| 世界运行 | 开启/暂停新决定、撤下可领养展示、按正式能力给活动建议；在途安全结算独立继续。暂停不能截断已发出的远端请求或吞掉费用 |
| 钱包与运营处理 | 只读流水；需调整时走现有有原因/权限/审计的资助或冲正命令，不直接改余额、不伪造工资 |
| 领养后 | 记录接手家庭与时间；退出公共领养池、停止平台居民管理，留可核对的公开历史；玩家之后的私密资料受正常权限限制 |

**状态分维度**：内容草稿/审核/发布，与归属未领养/已领养，与当前休息/工作/旅行是不同状态。不要用一个下拉框“改成旅游”掩盖缺失的真实行程，也不要用撤回内容发布把已经发生的领养撤销。

未被领养的角色媒体可按发布范围公开，未发布参考原件/内部备注不自动公开；被领养后的新私密资产按家庭权限读取。已公开资产的历史处理规则由 I/A 明确定稿，不许靠换个 URL 假装撤回所有历史副本。

## 7. 当前代码依据与实施缺口

本次为 2026-09-23 的**静态代码核对**，未运行本需求的业务用例或真实生成；共享工作区仍在变化。

- `web_residents/service.py` 和迁移 `m0240_residents.py` 已有驿站、稳定 pet_id、公开居民、领养后身份连续；原有服务说明特意限定为规则生活、不调用模型/生图。本需求是在这层增加受控能力。
- `web_agent_wiring.py::living_pets` 已把居民纳入生活；`family_model_enabled` 要家庭管理员，`projector.model_enabled` 使用该函数。因此无家庭居民模型决策需要 B 增加平台居民策略，不能只换一段性格文案。

## 9. 最小验收清单

1. 一份内容包重复导入不增加第二只；公开名字/形象/背景与大脑实际读取版本一致。
2. 原创/真实来源区分清楚；最低资产在手机上可辨、透明落地，无照片贴片冒充世界角色。
3. 0 钱居民有可执行生活与至少一种可用的零预付工作；不能发起付不起的旅行；工作只在完成后发一次工资。
4. 个体目标可影响合法选择；模型失败/额度用完有可解释的规则行为；大量围观不增加调用；公共池不会饿死某一只或挤掉已领养用户配额。
5. 决定、工作/旅行与公开事件相符；没有凭预设文案生成工资、已完成旅程或伪造回忆。
6. 两账号同时领养只有一个成功；在途接手不瞬移；钱包/经历保留；旧平台提案不能覆盖新家庭，家庭私密内容不泄露。

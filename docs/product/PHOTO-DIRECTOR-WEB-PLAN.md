## 1. 交付目标

主人能从照片里认出自己的那只宠物，看出它正在经历什么，也能从姿态和小习惯里感到熟悉。

- 外观写实：动物的脸、毛发、爪子和身体结构，避免人脸、人手、人体和卡通化。
- 允许平行世界生活：喝咖啡、乘火车、在家休息、戴飞行头盔。不能把“不变成人”实现成禁止这些生活动作。
- 自拍有贴近镜头、自然广角、轻微不完美的生活感；背景交代场所，避免每张都是背景完全虚化的证件照。
- DNA 影响动作、偏好和拍照方式；固定参考照与确认过的外貌信息约束长相。
- 照片、配文、通讯器、明信片与活动来自同一份事件事实。导演不创建旅程、扣钱、发勋章或改写经历。
- UI 样板动物不能充当当前宠物。无用户原照的原创伙伴使用稳定且明确标为生成的基准形象，不冒充还原了真实宠物。

首批四类：咖啡馆、火车途中、家中、飞行冒险。各场景必须有不同画面，而不是重复“坐在窗边”。

### 2.2 不能原样搬过来的问题

1. PhotoQualityEvaluator.evaluate_prompt 只看提示词关键词，其 pet_identity_score 不是像素相似度；旧质量报告不能作为真实照片验收。
2. 旧照片大脑存在疑似缺失导入：openai.py 使用 json、PhotoPerspective、PhotoMissionDraft、request/error 等但文件顶部未见对应导入。错误可能被 draft 的 except 吞成 None，退回规则。**这是静态发现，先由 P 禁网复现，再决定复用；不能称为已证明能运行的模型 Agent。**
3. iOS 中 receiveCurrentPhoto 的实际 UI 调用入口尚需核对；只找到定义和 API 方法不能宣称用户按钮闭环已接好。
4. 旧 PetRecord.dna、照片路径、公开媒体与网页家庭/DNA/私有媒体契约不同。不能导入整个旧 engine 直接套用。
5. 旧链路过度统一为第一人称自拍。新版明确自拍、伙伴帮拍、生活抓拍；用户请求自拍时仍严格遵守自拍构图。
6. 旧地点参考图会按 URL 下载。新版只接受数据层已核验且允许使用的媒体引用，不执行模型输出的任意地址。
7. 旧 last_remote_* 实例状态、模板后备、缓存和重试不能绕开 A 的预算、任务、未知结果与提交围栏。每次调用的状态跟着该次结果或异常走。
8. 旧生成失败可以返回地点照片作明信片图片（event_generator.py 的异常后备）。新版绝不把无宠物的环境图标为宠物自拍成功。
9. 旧 GET photo_mission 会进入模型/地图和 trace 写入，不能迁入网页纯读接口。旧缓存不含完整 DNA/照片/活动版本，不能直接沿用。
10. 提示词宣称存在的参考图与实际发送清单必须一致；环境下载失败时不能继续写“图二是店内参考”。旧 eval JSON 可加载与断言名称存在，不代表其中视觉断言已被执行。

## 3. 网页当前实际缺口

当前链路为 web_composition → web_agent_wiring → web_journey/illustrations → web_providers/images。

- character_of 只提供物种、名字与简略性格；自拍模板不直接读取完整的经授权 DNA。
- build_selfie_prompt 用名字、物种、地点、城市、场景与参考照拼提示词；到店场景写死“在店里靠窗的位置坐着”，明信片为邮筒旁情境。
- Web 适配器只传一张宠物参考；底层支持多参考不代表 Web 已使用地点图。
- 无参考时已有先生成证件照的代码，但 _render 当前忽略 portrait_saver 的保存结果。并发首次生成可能各用各的新图；需由 A 核对 CAS 失败后读回胜出基准的行为。
- A 正修未知结果、恢复与重画。可靠性测试不证明图片像不像、好不好看。
- 代码默认 Seedream。本方案不推断线上配置，也不在本批替换 GPT/Gemini。导演应与具体图片供应商解耦。

## 4. 目标架构

~~~text
已提交的活动或拍照请求
  → 只读上下文：身份参考、允许用于照片的 DNA、事件事实
  → 照片导演：动作、镜头、可见环境、情绪
  → 确定性编译：外貌/动物形态/事实约束 + 场景草稿
  → A 的任务与预算 → 生图适配器 → 私有媒体
  → 文件检查 + 独立视觉评测记录
  → 通讯器 / 明信片 / 收藏 / 手账内照片
~~~

导演是有边界的组件，不新增常驻进程或无限反思。页面刷新、地图动画、读取消息都不触发它。

### 4.1 内部契约提议

| 对象 | 内容 | 约束 |
|---|---|---|
| PhotoContext | pet/household、源事件、拍摄时刻、场景、身份/DNA/授权版本 | 只读事实，内部编号不进入用户文案 |
| IdentityReference | 参考 ID/摘要、来源、物种、确认过的外貌、已拥有配件 | 字节由媒体层读取，不把路径/秘密交给文本模型 |
| PhotoDNA | 获准用于照片的性格、习惯、兴趣、偏好 | 排除主人称呼、小暗号、私人往事和原始倾诉 |
| SceneFacts | 已发生动作、地点、当地时间、已核验天气/物件、交通状态、剧情类型 | 未知即未知；现实地点情境与幻想电影区分 |
| SceneDraft | 镜头枚举、动作/表情、构图、所用环境线索与事实引用 | 不允许更换宠物/城市/事件或添加未获得奖励 |
| DirectedPhoto | 编译提示词、参考角色与顺序、尺寸、提示版本、来源、提示检查 | rule/model 如实标记；提示检查与视觉结论分离 |

首批内部契约落在新目录，不扩大公共 Web API。需要共享 schema、字段或迁移时由 I 协调。

### 4.2 导演与固定规则

导演可选择“好奇地凑近镜头，杯子在画面下角”；编译器固定附加身份参考、动物结构和事实边界。

模型输出做结构校验，镜头/参考角色/场景类别只能取允许值。城市、宠物、活动来源从原始上下文编译，不接受模型换一个名字覆盖它。昵称与 DNA 都是输入数据，不能覆盖系统约束。

首批先有确定性 rule 模式和可注入模型端口，以替身验证解析/编译。完成许可和预算接线后再启用 model 模式；不可用时可明确采用规则场景，不假称模型生成。

### 4.3 外貌稳定

- 用户原照为主要锚点。后续作品持续引用原照，不连续仅用上一张生成图作为下一张的唯一参考。
- 原照缺失、损坏、无权限与原创伙伴没有照片分开处理。读取失败不能偷偷换成随机动物。
- 原创伙伴一次建立稳定基准。并发保存失败必须读回已保存的基准；两个不同生成结果不能同时当作同一宠物。
- 首版用一张合格基准照即可。多角度参考预留，但不能假称注册已支持多图。
- 身份参考、地点参考、UI 风格参考分角色。UI 图最多用于构图/色调，里面的动物不能混进身份。
- 多位家人共享同一宠物锚点，多只宠物严格隔离缓存和引用。

### 4.4 四类照片的具体要求

| 场景 | 画面建议 | 事实约束 | 重点验图 |
|---|---|---|---|
| 咖啡馆 | 近镜头自拍、桌角杯子、店内自然光；习惯影响姿态 | 已到店、已知点单；未知菜单不能当真实推荐 | 脸与花纹、爪子、杯子比例、场所 |
| 火车 | 近镜头，座位和窗外交代旅途，小配件可入镜 | 确实在车上、当地昼夜与活动 | 车厢空间、无多余肢体、不变成人身 |
| 家中 | 窝边、院子、已拥有毯子旁的生活照 | 配置的家环境和已拥有物件，不暴露现实住址 | 熟悉感、姿态、连续性 |
| 冒险 | 飞行头盔、驾驶舱、获奖后展示勋章 | 对应虚构剧情，不提前获得勋章 | 动物外观、装备自然、无受伤恐吓 |

若火车未接正式世界活动，可用明确标为评测场景的隔离输入做真实成图；不能算作正式火车链路完成。

变化来自习惯、动作与镜头，不靠换毛色/眼睛/体型。自拍为优先风格，但活动抓拍如实记为抓拍。

### 4.5 地点、时间、手账

店名无法保证复原真实装修。无环境参考时应表达该地点情境的 AI 想象，不声称还原店内，也不把图当消费评价证据。

拍摄时间来自源事件，不是生成完成时刻。生成期间宠物继续旅行，不自动否认已经发生的历史照片；参考身份替换、授权撤回等仍按明确版本政策阻止后续发送/发布。

攻略地址、价格、时刻保留结构化事实，通过可核对的排版承载。导演可生成手账内照片，首批不重写手账排版，也不只靠生图模型写文字来保存攻略事实。

## 5. 运行、授权与成本

1. 新模块无数据库写入和独立调度。接入 A/B 持有的调用点，由持有人实施或精确释放后 P 接手。
2. 每个照片事件最多一次导演文本请求；无效输出本地处理/明确后备，不无限改写。
3. 文本导演、图片生成分别记预算、模型与供应商，不把新增文本调用藏在图片额度里。许可映射或预算缺失就规则/离线模式。
4. 任务/缓存键包含源事件、pet、身份/DNA/授权版本、提示版本与配置版本。重画保留历史，新建尝试；更新参考、跨宠和撤权不可误复用。
5. 缓存命中也检查权限。生成照片授权和字段用途是必要条件，不能自行把“模型回信”开关等同于全部照片用途；I/A 明确新增文本处理的许可映射。
6. 供应商调用在短事务外，提交沿用领取、租约和版本保护。撤权不能消除已发出请求及其账本记录。
7. 提示修正不是重试许可。unknown 仍按 A 的恢复规则，导演不能另起请求掩盖未知结果。
8. 提示结构有效、图片生成成功、视觉验收通过是独立事实；不对用户显示未经验证的相似度分数。

## 6. 验收

### 6.1 先完成离线合同

- 同一身份引用贯穿四场景；不同宠物不串图/串缓存。
- 其他事实相同时，DNA 可影响动作/构图，身份和地点不变。这只证明信息使用。
- 明确自拍与抓拍分开；动物外观与允许的生活动作不互相矛盾。
- 未发生活动、未知天气/菜单、未拥有物件不成为已核验事实。
- 私密字段不进导演输入、提示、公开文案或证据摘要。
- 无权限、坏参考、无效输出、版本变化明确处理，没有隐藏网络调用。
- 输入中的指令式文本不能覆盖身份和事实引用。
- 用新进程、TZ=UTC、禁网替身、前后指纹及完整输出留证；不只测试包含 selfie 字样。

### 6.2 真实图片对照

先选择一只已获使用许可的测试宠物与固定基准照，或明确选择原创伙伴。不得任意读现有用户的媒体。

建议首轮8张：同一参考/模型/场景，旧模板4张、新导演4张，四场景各一对。若预算只允许4张，就只验新导演，不声称优于旧版。

- 留任务号、参考摘要、提示版本、事实输入、尺寸、模型配置、请求ID、耗时、用量/账本、图片摘要。支持 seed 才记录，不把 seed 当身份保证。
- 对照交错或随机顺序执行，固定配置与代码；版本变化不拼成同一组。
- 首轮最多4次导演文本请求、8次图片请求；视觉模型复核默认0次。金额上限按实际供应商报价确认，未知不能写0元；不自动追加补图。
- unknown 不自动重发凑张数；保留失败率和失败样本。
- 本地联系表展示原照、四场景图片与提示摘要，逐张人审；多模态模型可辅助，不能代替主人判断像不像。

建议质量门槛（待实际验证，非已实现成绩）：

| 维度 | 首批标准 |
|---|---|
| 身份 | 四张都能对应同一宠物；物种、主花纹、脸型、明显特征无明显漂移；无法判断单列 |
| 身体 | 无人脸/人手/人身、明显多余或缺失肢体、严重变形 |
| 事实 | 场景、活动、昼夜、配件与输入一致，不造新经历 |
| 生活感 | 四种场景可区分，至少两个适用场景能解释 DNA 如何影响画面 |
| 手机展示 | 主体清楚，自拍有背景线索，关键身体部位无不当裁切 |
| 主人意见 | 单独记录接受/不接受及原因，程序不能代填 |

一只宠物通过只覆盖这一组。跨物种、花纹、参考照质量的泛化在后续有预算时补测。

### 6.3 集成验收

隔离家庭内从实际拍照事件到任务、媒体、通讯器/明信片/收藏走通；刷新不再生图，重画有新尝试，未知文案准确。切换宠物不串图，撤权后媒体访问和后续发布符合权限。

记录使用替身还是真实供应商、固定评测场景还是自然时间世界。Q 的恢复/费用合同与视觉验收互补，任何一方通过都不替代另一方。

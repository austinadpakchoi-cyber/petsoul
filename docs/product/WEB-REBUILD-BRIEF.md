# PetSoul 网页重建：你去看世界，我偷菜养你

状态：2026-09-22 产品讨论修订。用户确认方向与 CTO 建议分开记录；本文不代表功能已实现，也不分配任何窗口职责。时间约束：96 小时，手机网页优先，目标部署地区香港。

本轮工程建议已进入总方案 v1.5：[意图与判断层](INTENT-DECISION-LAYER.md) 将分享、请求、否定、纠正和用途限制分别处理，优先改善接待与通讯。Jev 是可替换候选，框架只留接口/关闭开关/离线样例，中文对照与真实效果未验证；不能把识别结果当用户许可或执行成功，不阻塞比赛主线。

## 1. 用户已明确的方向

- 现实中主人出门、宠物守家；在平行世界反过来，主人经营和守家，支持宠物旅行与冒险。“我偷菜养你”和 QQ 农场式串门互偷是主动追求的趣味。
- 宠物在这个世界永远不会再受伤。参军、飞行员、保护地球等是酷炫的剧情表达，可以结合坐在战斗机里的 AI 照片；不设宠物真实受伤或等待付费救命的状态。
- 完整注册；有宠物可上传照片并收集样貌、性格、习惯与可选声音；没有宠物可以领养伙伴。
- 注册时有一位接待角色，让主人像向老师交代孩子一样介绍宠物、倾诉和托付。方案采用可跳过的对话与可编辑《入住叮嘱》，确认内容/用途后交给宠物，在家里兑现一个细节；名称与台词为建议，详见 [接待与记忆专题](RECEPTION-ONBOARDING-MEMORY.md)。
- 用户已明确确认“都是专属”：上传宠物、真实原型领养和原创领养伙伴全部采用专属关系，同一只宠物只归属一个家庭；不采用共同领养，也不把同一个角色复制发给多个用户。
- 共同的家成为首页，家园可发展种菜、养鱼、养鸡，收益支持旅行和城市解锁。宠物在家看守，外出时主人接手。
- 保留通讯、旅行地图、照片、明信片、回忆与收藏。旅行可以带回不同种子和稀有物资，并探索交易市场。
- 用户希望旅行在真实商家地图上有互动，国内高德、国外 Google，并研究扫街榜辅助选店；宠物进店喝咖啡等活动应在 UI 可见。朋友圈向宠物自己的公开微博式主页发展，其他宠物可以点赞和评论。详细建议和接口核实边界见 `MAP-VENUE-SOCIAL.md`。
- 新增特色“PetSoul 寻味引擎”：宠物有自己的口味，也记得主人喜好。按具体分店和菜品分别判断品质证据、口味匹配、本次价值和证据把握；虚拟经历不冒充真实口碑。96h 先做一条路线、两种偏好与可解释选店，框架先留接口，详见 [寻味专题](FOOD-DISCOVERY-ENGINE.md) 和总方案 v1.5。
- 真实交通与一起听看：飞机、火车、轮船、驾车按现实路线/时长在地图推进，采用喵航 Cat222 等独立稳定身份。用户已明确：交通工具旁显示音符/小电视，点击打开对应播放 UI，不做独立舱室场景。暂停媒体不暂停交通，驾驶时仅音频。首版默认核验时刻表，道路标预计，抵达后衔接寻味，详见 [交通影音专题](TRANSPORT-COMPANION-SYSTEM.md)。
- 公益领养希望以因交通事故离世的真实动物为原型；未来可能参与善后、火化，让这些伙伴在平台有名字、故事和新的家。
- 建立丰富的动物社会，未来发展原创角色、宠物 AI 影视和文旅合作。
- 募捐只是后续想法，现实公益将另行准备相应条件；现阶段可以使用游戏金币表达支持。

此前“多人互偷推后”“默认用救援替代英雄冒险”“玩家必然因被偷而拒绝旅行”等建议已修订。不得继续按这些旧建议限制用户已明确的方向。

## 2. 产品骨架（建议）

定位：一个宠物永远安全、拥有独立生活的动物星球。主人与宠物在这里有一个家；你支持它去看世界，它把经历与礼物带回家。

核心循环：经营/互偷 → 旅行基金 → 宠物旅行与冒险 → 稀有种子、物资、故事与照片 → 种植、制作、交换、装饰 → 更丰富的家与下一次旅程。

三个层次连接在一起：家园与邻里提供日常操作，旅行与职业冒险带来变化，关系与记忆赋予这些行为个人意义。影视和文旅从已建立的角色、地点和经历发展，不在第一天另建一套独立内容世界。

首页建议采用轻量 2D/2.5D 可互动场景：屋子、菜园、宠物、信箱和出发站。随地图和公开社交加入，导航建议更新为“家 / 旅途 / 星球圈 / 通讯”，回忆和收藏从家中的相册/展示柜进入；导航尚未冻结。重要操作保留清晰按钮，不依赖悬停或精细拖拽。

## 3. 角色反转、互偷与收益（建议规则，尚未冻结数值）

- 宠物在家保护菜园；旅行中开放按规则互偷，主人可以收获、巡院、串门。
- 互偷发生在真实账号之间，留下可回访记录；NPC 菜园如使用应明确其身份，不伪装真实玩家。
- 偷取成熟作物中的有限份额，不触及私人照片、纪念物、已入账旅费。一个成熟周期有总可偷上限与单人限制；保留真实损失和社交趣味，具体比例靠试玩调整。
- 宠物知道主人为旅费做的事，并按性格回应。例如收到旅费去看海；看到邻居留言后调侃“听说你又去拔萝卜了”。回应必须依据实际事件。
- 旅行带回家园无法直接生产的种子、配方或纪念物，形成互补收益。玩家是否愿意出发应实测，不能预先断言。
- 生长、成熟、守护、互偷、收益都由服务器判定；重复请求不能重复结算。其他用户对公开菜园的有限操作权限与宠物私有数据权限分开。

## 4. 稀有物资与交易（方向已认可，机制待定）

先定义物品的用途，再增加稀有度：种子用来种植，材料用于制作/升级，地方纪念品用于装饰和收藏。不同目的地应有不同的获得物，旅行和交易才有实际需求。

建议首期使用同一种游戏金币，个人照片、关系记忆、荣誉勋章不进入市场；可交易范围限定为种子与物资。宠物本身不作为商品。

发展顺序：NPC 商店建立基本买卖与用途 → 少量物资的玩家固定价挂牌 → 根据真实供需扩展交易。NPC 商店必须叫商店，不作为玩家市场已完成的证明。

若比赛主线在 H48 前稳定，可争取一种物资的固定价挂牌/购买；否则放到下一阶段。完整市场需要库存托管、原子成交、并发购买去重、取消退还和价格/产出平衡，不能只实现挂牌页面。

## 5. 注册、画像与公益领养

完整账号注册和宠物档案完善分开。建议先完成名字、照片或领养角色、几个性格特点与主人称呼，再逐步收集共同记忆、习惯和声音。采集声音、播放声音、生成拟声是不同能力，不将上传音频宣传成声音复刻。

性格需要影响行动选择、回复表达、朋友关系和礼物偏好；不能只在资料页展示几个标签。身份档案与照片生成保持一致，避免不同场景里宠物外貌不断变化。

真实原型领养的产品建议：

- 领养卡首先介绍名字、性格、爱好和梦想，离世经历以可选择展开的简短背景呈现，不用事故画面作为默认吸引入口。
- “谢谢你给我一个家”用于建立关系的仪式。之后角色持续拥有自己的生活和新经历，不反复以悲惨身世要求用户消费或上线。
- 真实原型、已完成的现实善后、平台虚构故事分别标明。核实来源、原主人/提供者关系、素材使用授权与实际处理记录；未知信息不补成事实。
- 有可核实且可用的材料时，可纳入少量真实原型；不足时使用明确标识的原创伙伴，不能编造救助、火化或捐赠成果。
- 现实公益是需要合作执行和记录的工作流，不是生成一个角色即可宣称已经完成。

已确认决策：全部专属。真实原型和原创领养伙伴都具有独立身份与归属，同一只宠物领养成功后退出可领养列表；不能用多个数据库实例掩盖同一个角色被重复发放。先前“共同守护”及“可重复领养角色模板”的建议已撤回。

实现要求：领养归属必须在服务器端原子确认，多人同时申请同一只宠物最多一人成功，其他人获得明确的已领养结果。真实原型需要可追溯的唯一来源标识；用户上传的重复或归属争议处理机制另行设计，不能假称已解决。

设计建议：每只新原创伙伴有自己的身份、外观特征与性格组合；访邻、交朋友和参加公共剧情不改变其家庭归属。用户暂时离线不导致宠物被自动收回或重新发放；如未来考虑主动转交或注销后的安排，需要另行确定规则。

## 6. 英雄冒险、金币活动与现实公益

保留用户希望的飞行员、侦探、星球守护者等身份。冒险有惊喜、幽默和成就感，世界规则保证宠物安全；危险仅作为虚构剧情气氛，不出现失去宠物的惩罚。

比赛可选择一个原创英雄场景，例如安全完成巡航、带回稀有种子与飞行徽章，生成宠物坐在驾驶舱里的照片并寄给主人。照片与奖励对应同一次实际游戏事件；图像、视频若预制或生成失败，按实际能力展示，不冒充实时生成成功。

游戏金币可参加“星球补给站”等共同建设活动，推进世界内设施或纪念奖励。金币不默认折算现实捐款。将来如果有真实配捐，应分别列明实际出资方、规则和兑现记录。

若剧情借鉴真实灾害，现实信息与虚构演绎分开说明。真实募捐不纳入当前默认交付范围；用户尚未授权收款、支出或对外承诺。

## 7. 原创 IP、AI 影视与文旅

先让少量原创角色形成稳定的名字、外观、性格、职业与关系。每次真实游戏经历保存为事件，后续由这些事件生成图文回忆、短片或角色连续故事，保持人物与经历一致。

可能形成三个内容层次：用户自己的宠物故事；星球公共角色的连续剧情；围绕城市与文化主题的旅行章节。用户宠物或真实领养原型进入平台公开影视、宣传或商业合作，需要独立的使用范围确认，上传或领养本身不代表同意代言。

文旅建议先用一座城市证明体验：可识别的地标、当地生活细节、当地角色与特产、宠物的个人经历。进一步合作要由实际内容与用户反馈验证，不能把未来爆款 IP 或文旅合作写成既成成果。

## 8. 96 小时首发建议

主线：真实注册 → 上传/专属领养 → 家园 → 一套种植玩法 → 两账号真实互偷 → 旅费 → 真实地点短途旅行与可见店内互动 → 个性化来信/照片与公开动态 → 第二个账号的宠物互动 → 稀有种子或纪念物回家。英雄冒险与照片复用同一事件体系，先后按进度安排。

建议预算：一个精致家园、一套作物规则、少量伙伴、一个目的地、一个英雄事件。新手短途本身设计为较短体验，欢迎作物可以立即收获；不暗中修改正常世界时间。

有条件再做：一种物资的玩家固定价交易、可选音频、第二目的地。下一阶段：鱼塘鸡舍、复杂市场、更多真实公益合作、连续 AI 影视生产、多人大世界。

AI 负责角色表达和画面，确定的游戏规则负责归属、库存、金币与奖励。网页或内容生成失败时，玩家已有进度仍能保存和恢复。

复用既有后端的旅行、通讯、图片和回忆能力；新增网页、家园和社交经营。公开体验前补齐先前本地审计发现的归属校验、媒体访问与重复请求问题。代码、fixture、浏览器、真实供应商与部署证据分别记录。

# 爪爪驾校 v1：主人陪考，宠物拿证（方案与规格）

- 版本：2026-09-22，窗口 `claude-20260922-014933-307b`。
- 依据：用户在对话中给出的《爪爪驾校》玩法方案，要点包括：四科、每科一次补考、两次不过冷却 7×24 小时、服务端复算、拿证解锁自驾。
- 替代：契约 0.2.5 里“宠物按掌握程度自动答题”的驾考（`/driving/practice`、`/driving/exam`）。前端还没有接入旧接口，本版直接替换，契约升到 **0.3.0**。
- 核心体验：**以前是你开车带它出门，这一次，你陪它学会开车。**
  - 主人负责判断和操作；宠物在车里执行，性格体现在动作、表情和话语里。
  - **正式成绩只由操作与规则决定，不由模型或随机数决定。**

## 2. 科目与通过条件

| 科目 | 主题 | 玩法 | 正式通过 |
|---|---|---|---|
| `s1` 科目一：认识路上的规则 | 看得懂、判断对 | 10 题，题型有看场景选择、拖放标志、判断先后；每题 10 分 | ≥ 90 分 |
| `s2` 科目二：把小车开稳 | 方向与空间 | 倒车入库 → 侧方停车 → 弯道行驶，连续一场 | 三项都完成，且综合 ≥ 80 分 |
| `s3` 科目三：第一次上路 | 连续驾驶与观察 | 小城路线：出发前检查、正确起步、停车让行路口、礼让过街居民、红绿灯、按指示右转、到达后靠边停稳 | 完成路线，≥ 80 分，未触发红线 |
| `s4` 科目四：遇到情况怎么办 | 情境判断 | 五段生活动画，每段两个判断，共 10 个，每个 10 分 | ≥ 90 分 |

- **解锁顺序**：正式考试按科目一 → 二 → 三 → 四依次解锁；上课和练习在报名后随时可以进行。
- **卷面**：
  - 科一、科四从经过审核的固定题库抽取，覆盖固定知识点，不由模型临时编题；
  - 补考换一组题或一局场地，难度与考查范围相当。

## 3. 考试机会与冷却（服务端规则）

| 当前状态 | 正式考试资格 |
|---|---|
| 该科还没考过 | 首次考试 ＋ 一次补考 |
| 首次没通过 | 还剩一次补考 |
| 补考也没通过 | 从第二次失败结算起，冷却 **7×24 小时** |
| 冷却结束 | 开始新一轮，重新获得首次考试 ＋ 一次补考 |
| 已通过 | 永久保留，不再消耗机会 |

- 冷却与机会按**宠物、按科目**计算，由服务器时间决定：`可再次考试时间 ＝ 第二次失败结算时间 ＋ 7×24 小时`。换设备、退出登录、改名字都不会重置。
- **“一次”指一整场正式考试。** 一次压线只扣分，不直接消耗机会；整场结算为未通过才计一次失败。
- **计次时机**：正式考局在资源加载完成、用户点“开始考试”（`begin`）之后才计次。建立后 1 小时内没有开始的考局作废，不计次。
- **暂停与续考**：
  - 断线、切后台时自动暂停；
  - 练习和考试的操作每秒保存一次；
  - 回来时按服务端已保存的操作续考，不能重新抽题，也不能抹掉已经发生的扣分；
  - 同一只宠物同一时间只能有一场未结束的正式考试。
- **放弃**：主动放弃已经开始的正式考试，计为本次未通过；接口要求二次确认（`confirm: true`）。
- **平台故障**：服务端复算出错的考局作废，不计次。
- **不卖机会**：不卖补考次数、不卖清除冷却、不用广告缩短等待，也不因为没考过降低亲密度或责怪主人。

## 4. 驾驶模拟与服务端复算（前后端共用规格）

驾驶小游戏在前端实时运行；服务端用同一套确定性模拟，根据**操作记录**独立复算，客户端上报的分数一律无效。

### 4.1 确定性

- **固定步长**：每秒 30 个 tick。渲染可以插值，结算只看 tick。
- **只用可复现的运算**：只用 IEEE 双精度的加减乘除和 `sqrt`，Python 与 JavaScript 结果逐位相同；不用 `sin`、`cos`、`tan` 等实现相关的函数：
  - 转向角的正切值由服务端写进场地配置；
  - 小角度旋转用泰勒展开：`c = 1 - w*w/2 + w*w*w*w/24`，`s = w - w*w*w/6 + w*w*w*w*w/120`。
- **数值来源**：所有常数（车身尺寸、正切表、速度、加速度、刹车、线、锥桶、目标区、时限）都来自服务端下发的场地配置（`course`），前端不另存常数。
- **互相校验**：样例文件 `PetJourneyWeb/tests/fixtures/driving-golden.json` 由 `scripts/gen_driving_fixtures.py` 从后端生成；前端测试逐位比对，后端测试检查样例是否过期。

### 4.2 车辆模型（每个 tick 的计算顺序）

1. 应用这个 tick 的操作事件：转向目标、油门、刹车、换挡请求、转向灯、检查项、邀请处理。**换挡只在车速为 0 时生效。**
2. 转向：当前转向档位 `s` 向目标移动 1 档（范围 ±12 档，满舵 34°）。
3. 速度：
   - 刹车：朝 0 减 `brake`；
   - 否则踩油门：D 挡加 `accel`，不超过 `vmax_f`；R 挡减 `accel`，不低于 `-vmax_r`；
   - 都不踩：朝 0 减 `coast`。
4. 朝向：`w = v * tan[s] / wheelbase`；`w ≠ 0` 时用上面的近似旋转朝向单位向量，再归一化。
5. 位置（以后轴中心为参考点）：`x += v*hx`，`y += v*hy`。
6. 判定：
   - 车身矩形与计分线相交：“压线”按连续段计一次；
   - 与锥桶相交：每个锥桶最多计一次；
   - 车身出界：失败；
   - 目标区到位保持计时；
   - 科三的路线检查点。

### 4.3 判定与扣分

| 科目 | 事件 | 处理 |
|---|---|---|
| 科二 | 一次连续压线（任一计分线） | −5 |
| 科二 | 碰到一个训练锥（每个只计一次） | −10 |
| 科二 | 该项超时、车身离开训练场 | 该科不通过 |
| 科二 | 到位：整车在目标区内，角度偏差 ≤ 12°，车速为 0，连续保持 2 秒（弯道终点保持 1 秒） | 完成该项 |
| 科三 | 起步前没完成三项检查（系安全带、调后视镜、观察周围） | −10（一次） |
| 科三 | 起步时没打左转灯 | −5（一次） |
| 科三 | 停车让行路口没停稳就越过停止线 | −10 |
| 科三 | 右转前没打右转灯 | −10 |
| 科三 | 超速（进入超速状态一次） | −5 |
| 科三 | 压到路沿或中心线（连续段） | −5 |
| 科三 | 开车时打开视频邀请 | −10（不真的打开视频） |
| 科三 **红线** | 闯已经清楚显示的红灯；冲进居民正在通过的人行横道；开出道路；超时 | 自动制动，本次不通过 |

这些数值是游戏调参的起点，不代表现实驾考标准。所有扣分项和红线，都在教学页和开考说明里提前列出。

### 4.4 操作记录与上传

- 每一项单独从 tick 0 开始记录。事件格式为 `{t, c, v}`：

  | `c` | 含义 | `v` |
  |---|---|---|
  | `s` | 转向目标档位 | −12..12 |
  | `t` | 油门 | 0 / 1 |
  | `b` | 刹车 | 0 / 1 |
  | `g` | 换挡 | 1＝D，−1＝R |
  | `k` | 转向灯 | −1 / 0 / 1 |
  | `c` | 出发前检查 | 1..3 |
  | `v` | 视频邀请 | 0＝稍后，1＝打开 |

- 前端大约每秒上传一段 `{item_index, from_tick, upto_tick, events}`；本地检测到压线、碰锥、到位或出界时立即上传；暂停或切后台时也立即上传。
- 服务端只接受从已提交位置连续往后的片段：
  - 与已提交片段完全相同的重发，原样返回当前状态（天然幂等）；
  - 不连续或内容不同，返回 409，前端按服务端状态重新同步。
- 服务端逐段复算并保存模拟快照。一旦复算出失败（超时、出界、红线），当场结算。

## 5. 接口（契约 0.3.0，前缀 `/api/v1/web`）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/driving` | 驾校总览：阶段、四科状态（锁定 / 可考 / 考试中 / 冷却中 / 已通过）、机会、冷却截止时间、未结束的考局、驾照、借车券、仪式是否完成 |
| GET | `/driving/curriculum` | 课程：教练、四科说明、教学步骤、扣分项与红线、操作说明、补考规则、按性格的台词、`reasons`（判定事件的说明文字，前端实时提示与成绩单共用，前端不另存文案） |
| POST | `/driving/enroll` | 陪 TA 报名（TA 有了愿望一天后也会自己报名） |
| POST | `/driving/sessions` | 建立练习或正式考局 `{subject, mode, item?}`；**必须带 Idempotency-Key**；正式考局先检查解锁、机会、冷却，以及是否已有未结束的考局 |
| GET | `/driving/sessions/{id}` | 考局：题目（不含答案）或场地配置、已保存的作答或操作、结果 |
| POST | `/driving/sessions/{id}/begin` | 资源加载完成，正式开始；从这一刻起计次 |
| PUT | `/driving/sessions/{id}/answers` | 科一、科四逐题保存作答。练习模式立即给讲解；正式模式在交卷前不给任何提示 |
| POST | `/driving/sessions/{id}/inputs` | 科二、科三上传操作片段，返回服务端复算的事件、分数与状态快照 |
| POST | `/driving/sessions/{id}/pause` | 记录暂停 |
| POST | `/driving/sessions/{id}/submit` | 交卷或完成结算，只结算一次；重复请求返回同一结果 |
| POST | `/driving/sessions/{id}/abandon` | `{confirm: true}`：正式考局计为未通过；练习直接结束 |
| GET | `/driving/history` | 本宠物最近的考局与结果，只给主人看 |
| POST | `/driving/ceremony` | 领证仪式：只做一次；返回驾照、合影纪念、借车券与 TA 的话 |

- 跨账号访问别人的考局返回 404。
- 所有写操作都要求 CSRF。
- 考试历史默认不公开。
- 考局状态枚举在契约里叫 `SchoolSessionState`（`preparing / running / settled / void`），与登录用的 `SessionState` 区分；契约生成脚本遇到重名直接拒绝生成。
- 时间一律 UTC、以 `Z` 结尾（包括错误 `details.cooldown_until`）。

## 6. 拿证与世界能力

- **拿证**：第四科通过、四科齐全时，在同一次提交里完成：
  - 签发 `PetSoul · 爪爪驾驶证`（C 照，一只宠物一本）；
  - 发一张绑定的“驾校借车券”（第一次自驾免租车费）；
  - 登记一条拿证消息。
  消息投递失败不影响驾照。
- **领证仪式**（`/driving/ceremony`）：教练盖爪印章，TA 接过证件，你们合影，生成一张“领证合影”收藏。只有主人开启“生成照片”且配置了生图时才会生成写实照片（付费）；否则是纸质纪念卡。
- **自驾资格**：没有驾照不能自驾（服务端 403），乘飞机、火车、轮船、公交、出租车不受影响。有驾照也要租车；借车券只能抵一次。
- **卡面**：写明它属于 PetSoul 世界，不代表现实驾驶资格；签发机构“爪爪驾校（PetSoul 星球交通局）”为虚构；驾照不能交易或转赠。

## 7. 宠物与教练

- **龟教练·慢慢**（原创居民）：“方向可以慢慢找，停车要稳稳当当。”教练的播报保持中立，例如“前方路口右转”，不告诉答案。
- **宠物的话**：按 DNA 行为画像选用固定模板，爱热闹的会兴奋，恋家安静的只是抬头看你一眼。
  - 不会随机干扰操作，不会在正式考试中暗示答案；
  - 没考过时不责怪主人，只说“这轮先到这里，我们把要练的地方记下来了”。
- **TA 自己会做的事**：产生学车愿望；报名满一天后邀请主人陪练；冷却结束时告诉主人可以再约考试。**TA 不会自己去考试。**

## 8. 前端模块

- **位置**：`PetJourneyWeb/src/features/driving_school/`，模块自动发现，不修改其他窗口正在改的页面。
- **路由**：
  - `/school`：驾校总览；
  - `/school/subject/:subject`：上课、练习、考试入口；
  - `/school/session/:sessionId`：全屏考局，收起底部导航；
  - `/school/result/:sessionId`：成绩、回放、错题；
  - `/school/ceremony`：领证仪式；
  - `/school/try`：比赛现场的倒车入库体验版，只在本地运行，不连后端，不计成绩。
- **入口**：
  - 星球圈新增插槽 `circle.places`，主入口是“爪爪驾校”；
  - 家园面板 `home.panels` 放一张紧凑的进度卡；
  - 旅途卡片 `journey.cards` 在没驾照时提示“先取得爪爪驾照”。
- **考试页布局**（以 390×844 为母版）：
  - 顶部约 10%：科目、项目、分数、剩余时间、暂停；
  - 中部约 60%：训练场；
  - 底部约 30%：左手方向盘（也可以切换成“左 / 回正 / 右”按钮），右手刹车和油门，停稳后切 D / R。
- **练习与正式考试的区别**：练习显示预测轨迹、目标车位和分步提示；正式考试取消这些提示，只保留边线、车位与挡位。
- **反馈**：压线、碰锥、到位都有视觉提示，静音也能玩；尊重“减少动态效果”；支持键盘操作（方向键、空格刹车、D/R 换挡），方便无障碍使用和桌面测试。
- **实现要点**（2026-09-22 已实现）：
  - `sim/`：与后端 `sim.py`、`replay.py` 逐行对应；`drive/engine.ts` 只在控制变化时记操作事件；`drive/uploader.ts` 严格按顺序上传、网络失败原样重发、409 按服务端快照重建；离开页面时把最后一段操作收尾并在后台发完，马上离开也不会丢掉刚发生的扣分；
  - 本地快照与服务端快照逐段比对（车辆状态、判定事件数、状态），对不上就以服务端为准重新同步；
  - `drive/render.ts` 用主题变量绘制（日间 / 夜间自动跟随）；场地类项目整场可见，科三跟车视野约 40 米；
  - 页面与演示数据按需加载，主包只含三个入口卡片；
  - fixture 模式（`fixture.ts`）在内存里按同一套规则运行，网址参数 `?school_demo=enrolled|licensed` 可以从“已报名”或“已拿证”开始演示；
  - 考局容器带只读的 `data-tick`、`data-item`，供自动化测试核对续考位置。
